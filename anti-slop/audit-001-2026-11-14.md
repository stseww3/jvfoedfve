## Overall

This is a clean, honest, single-purpose tool, not a slop landing page. There are **no** fabricated stats, fake testimonials, buzzwords, generic CTAs, trend-stacking, cloned layouts, or dead controls. All *text* contrast passes WCAG AA (verified with the skill's `contrast-check.py`, not eyeballed). So most of the list below is completeness and polish, with a handful of genuine Hard-Gate items (em dash, focus outline, document semantics, reduced-motion).

Priority follows the anti-slop rule tier: **HIGH** = Hard Gate (absolute), **MEDIUM** = Purpose-Gate / a11y depth, **LOW** = Quality Locks / liveliness / polish.

## HIGH (Hard Gate)

### 1. Em dash in shipped text and in the bullet marker  (R-02)
- **Where:** `index.html:44` error message: `could not load terms.json — run a local server (...)`; `styles.css:195` list bullet: `content: "— ";`
- **Problem:** R-02 forbids the `—` character in any UI text the project ships.
- **Fix:** change the error copy to use a colon/period/parentheses; swap the definition bullet marker to a hyphen `-` or a real styled marker. One-line, zero visual cost.

### 2. No loading state  (R-27)
- **Where:** `app.js` `init()` / `index.html` (only `#empty` and `#error` exist)
- **Problem:** R-27 requires empty + loading + error for any data view. There's empty and error, but no loading state. It's invisible today only because `terms.json` is local and instant; on a slow connection the page is blank with no feedback.
- **Fix:** show a short "loading terms..." placeholder (text, screen-reader announced) until the fetch resolves.

### 3. Focus outline removed on search, weak/absent elsewhere  (R-32)
- **Where:** `styles.css:85` `input:focus { outline: none; ... }` (replaced only by a faint `#808080 -> #c0c0c0` border change); no `:focus-visible` rule for `.chip` buttons or links (they rely on the browser default only)
- **Problem:** R-32 forbids `outline: none` without a clearly visible replacement. The border-color swap is subtle and the only custom focus style on the page.
- **Fix:** add one base-layer `:focus-visible` style (e.g. a 2px high-contrast ring at >=3:1) for inputs, chips, and links; keep it consistent across the page.

### 4. Missing document landmarks  (R-39)
- **Where:** `index.html` (content lives in `<div class="container">`; the only grouping element is `<section class="grid">`)
- **Problem:** whole-document R-39 requires `<header>` / `<main>` / `<footer>` landmarks. Screen-reader users navigate by landmarks; there are none.
- **Fix:** wrap the title/subtitle/search in `<header>`, the results in `<main>`, and (optionally) move the GitHub link into a `<footer>` or `<nav>`.

### 5. Heading levels skip h2  (R-39)
- **Where:** `index.html:24-25` `<h1>` then `<h3>` (subtitle); term cards render as `<h2>` after load, so the reading order is h1 -> h3 -> h2
- **Problem:** R-39 forbids skipped heading levels. The subtitle jumps h1 to h3.
- **Fix:** make the subtitle a styled `<p>` (it's a tagline, not a section heading), so the only headings are h1 (title) and h2 (terms).

### 6. No `prefers-reduced-motion` handling; `transition: all` runs for everyone  (R-39)
- **Where:** `styles.css:9-10` `* { transition: all 200ms linear; }` (the `.preload` guard at `:13-17` only suppresses transitions during initial load, not for reduced-motion users)
- **Problem:** R-39 requires non-essential motion to stop under `prefers-reduced-motion: reduce`. Hover scales / color transitions still animate for users who asked for less motion.
- **Fix:** add a `@media (prefers-reduced-motion: reduce)` block that zeroes transitions; see also #10 about scoping `transition`.

### 7. Render-blocking web font in `<head>`  (R-40)
- **Where:** `index.html:10-13` Google Fonts `<link rel="stylesheet">` (with `preconnect`, good) loading `Inconsolata:wght@200..900`
- **Problem:** R-40 discourages render-blocking third-party resources in `<head>`; pulling the full 200..900 weight range ships more font than the UI uses (it uses ~400/500/600).
- **Fix:** subset the weights to the ones actually used and/or self-host; add `font-display: swap` is already implied, but reserve against layout shift. Lowest-effort win: trim the weight range.

## MEDIUM (Purpose-Gate / accessibility depth)

### 8. Low non-text contrast on alias chips; body grey is marginal  (R-25 / WCAG 1.4.11)
- **Where:** `styles.css:210` alias chip border `#404040` on card `#121212` = **1.81:1** (fails the 3:1 non-text bar); primary grey body text `#808080` on `#121212` = **4.74:1** (passes AA, but it's the floor, and this is a *reading* site)
- **Problem:** the alias chip outline is nearly invisible to low-vision users; the main definition grey sits right at the minimum.
- **Fix:** lift the alias border to ~`#5a5a5a`+ (>=3:1), and nudge the body grey a notch (e.g. `#9a9a9a`) for comfortable reading.

### 9. Monospace used for all prose, including definitions  (R-06)
- **Where:** `styles.css:8` global `font-family: "Inconsolata", ...monospace` on `*`
- **Problem:** monospace is great identity for the wordmark and the short terms (it sells the OG-trading/terminal vibe, which is a real reason), but running every multi-line definition in monospace hurts readability, which is the whole job of a dictionary.
- **Fix:** keep Inconsolata for the wordmark, terms, badges, and chrome; set definitions/paragraph text in a readable companion (a clean humanist sans or a readable mono at a comfortable size/line-height). Write the one-line reason for each (R-31).

### 10. `transition: all` on the universal selector  (R-19)
- **Where:** `styles.css:9-10`
- **Problem:** `transition: all` on `*` animates every property on every element (including layout-affecting ones), which is wasteful and can cause subtle jank; it's also the AI-default way to "add smoothness" without intent.
- **Fix:** scope transitions to the specific properties that should animate (e.g. `border-color`, `color`, `transform`) on the specific elements (chips, cards, inputs).

## LOW (Quality Locks / liveliness / polish)

### 11. Dark-only, no light/dark toggle  (R-21)
- **Problem:** dark default is *defensible identity* here (the OG-trading/forum scene lives on dark UIs), so this is not a slop auto-fail. But no light option is offered at all.
- **Fix (optional):** add a persisted light/dark toggle (both modes fully working, R-34), or consciously decide dark-only is the brand and write that reason down (R-31). Your call, not a requirement.

### 12. No single deliberate accent; palette edges toward sterile  (Liveliness / Part 3)
- **Problem:** the palette is pure black/white/greys with zero accent. It has a monospace identity motif, so it's not fully "sterile default", but the "one deliberate accent" lever is unused, which flattens hierarchy (categories, active filter, matches all read as grey/white).
- **Fix (optional):** introduce one restrained accent (e.g. a single green used only for the active filter + match highlight + a hairline), nothing more. One color, used sparingly, at the key moments.

### 13. No written design rationale  (R-31)
- **Problem:** there's no `DESIGN.md` capturing why mono / why dark / why this layout. R-31 (the keystone) wants a one-line reason per major decision.
- **Fix (optional):** add a short `DESIGN.md` so future changes stay on-identity.

### 14. No favicon, no social-preview (OG/Twitter) meta  (polish, outside strict R-set)
- **Where:** `index.html` `<head>` has `theme-color` but no `<link rel="icon">` and no `og:*` / `twitter:*` tags
- **Problem:** not an anti-slop rule violation, but it's the thing that makes the tab and shared links look unfinished (you flagged this yourself earlier). High payoff for the "finished product" feel, especially before pointing `dictionary.iraqies.love` at it.
- **Fix:** add an SVG favicon + an `og:image` social card + the OG/Twitter meta.
