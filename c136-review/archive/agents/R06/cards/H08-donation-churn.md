# H08 捐款空转：对倒、后排往更密的号捐、到账被截断、捐给空壳、被拒了反复重试（DN-pingpong / DN-to-overcap / DN-fee-exceeds-delivery / DN-husk-donate / DN-small-pct / DN-quota-retry-loop）

**假设**：捐款的三成进了手续费，不是因为每笔的比例小，而是因为同一笔兵在同队的号之间来回转、捐给已经快满的号、捐给已经离开的号。收到的兵不到一半在 300 拍里打了出去。

**定义**（录像真值，`donflow.py`）
- 手续费 = 捐款人余额的 6.25%（`floor(64B/1024)`），跟 pct 无关；到账 = min(`floor(B×(pct+1)/1024)`，B − 手续费，收款人离硬上限的余量 150×地 − 兵)。损耗率 = 手续费 ÷（手续费 + 到账）；不截断时 = 64 ÷ (pct + 65)。
- 对倒 = A→B 执行后 150 拍内 B→A 也执行。
- 被截断 = 到账不到名义值的 90%。
- 后排 = 捐款时被围的捐款人（`boxedIn`：nb=0 且 neut=0）；由 pct 反推：185 / 280 = 被围的盈余捐款，153 = 不被围的盈余捐款，155 = 救援，<155 的其他值 = 救援被 `maxSafePct` 钳小。
- 收款窗口 = 同一个收款人相隔 ≤300 拍的几笔并成 [第一笔, 最后一笔 + 300]。
- 日志侧（`patterns.py`）：按捐款人自己的余额读数判一条 `[HL-DONATE]` 是否执行。

**脚本**：`scripts/donflow.py <局>`、`scripts/crossmatch.py donflow|money`、`scripts/patterns.py count|cost`、单局 `scripts/simdigest.py <局> don|probe`。

**对照 / 效应**
- 任务卡问的小比例捐款（pct 67~185）：常规档 153 / 155 / 185 的理论损耗率是 29.4% / 29.1% / 25.6%，实际 31%。<150 的档 86 笔、手续费 731 万换到账 1,057 万，不到全部手续费的一成。小比例每笔都亏三成以上，但不是大头。
- 大头按手续费排：对倒 3,714 万（48%）；被截断 2,082 万（27%）；给空壳 665 万（9%）；<150 的小档 731 万（9%）。这几项互相重叠，不能相加。
- 后排（被围的号）捐出了全部到账的 48%。它们从密度 55 就开始捐（中位 80），收款人密度中位 97；64% 的笔数是稀的号捐给更密的号，45% 的收款人已过软上限，被截断或到账为 0 的 126 笔里 71 笔出在这一支。
- 救援捐款（收款人正被打）只占到账的 18%，而且是效果最差的一支：收款人之后 300 拍把一半以上打出去的只有 43%~44%，41%~49% 一条出兵指令都没有，135 个有读数的收款人里 34 个阵亡。原因见 H05：收到兵的号照样过不了地价闸和保底线。
- 没看过的 23 局同版本对局，日志侧损耗率 31.8%、对倒 173 对、捐给空壳 14.0%：与我的 15 局一致。
- 录像里外人之间的捐款（7 局 475 笔、到账 1.00 亿）有 85 笔是 pct ≥900（到账 2,866 万）：一次给足，pct=1023 的理论损耗率是 5.9%。我方 834 笔里没有一笔 ≥300。

**不是什么**
- 不是「每笔捐得太少」：把 153 提到 280 只能把理论损耗率从 29% 降到 19%，而对倒和截断照旧。
- 不是配额不够造成的损耗：被拒的捐款不收手续费。配额的代价是占掉决策拍（见下）。
- ECO_BANK 角色在这 15 局里不存在：它是后端选点协调器（`spawn-coordinator-c110.mjs`）分配的出生角色，15 局 `HL-SPAWN-BACKEND` 0 行，局内代码也不读角色。

**代码位置**：`tryDonateToTeammate` L4369-4499。
- L4372：`t ≥ 400`、两次捐款至少隔 18 拍。L4374 `boxedIn = nb.length === 0 && neutral === 0`。
- L4382-4389：`coastGuardFloor` = 有海岸且 t≥1100 时 68×地，否则 18×地；`safeFloor = max(coastGuardFloor, 有敌方真人邻居 ? safeAt(g,−1) : 0)`（封顶 88×地）；正被真人打或 `B ≤ 1.10×safeFloor` 不捐；`maxSafePct = floor((B − 1.08×safeFloor)×1024/B)`，<55 不捐。
- 救援 L4423-4446：同队的池内号正被真人打（压上来的兵 ≥ 它余额的 8% 或它密度 <75），我密度 ≥ max(55, 它 + 15)：`pct = min(maxSafePct, 纯内陆 ? 240 : 155)`，≥55 就发。pct 55~63 时到账不高于手续费。小比例就是从这里来的：有敌方真人邻居、底线取到 88×地 时，捐款人密度 100.5 对应 pct 55，密度 112 才到 155；只有海岸底线（68×地）时是密度 77.7 → 55、86.6 → 155。
- 盈余 L4462-4497：不被围要密度 ≥112，被围只要 ≥55；候选是同队的池内号、≥600 格、密度 <132；打分 `600 + (在途兵)/500 + (135 − 密度)×3 + min(150, 地/500)`；合格条件 L4482 是「Boss，或我被围，或它的在途兵 > 余额的 4%，或（我密度 ≥120 且它 <98）」。`pct = 被围 ? (密度 >110 ? 280 : 185) : 153`（L4489），这一支不受 `maxSafePct` 限制。
- 整个函数不看：收款人是否已离开（空壳的名字还在池里）；收款人离硬上限还有多少余量；收款人余额是否为负；上一笔是不是它刚捐给我的；这一笔过不过得了配额。
- 配额：`Policy.send` 一侧有影子配额 `updateShadowQuota`（L3810-3841），只在 `isNoFullSend` 时用于陆攻（L3854）；捐款不查。被拒的捐款每 18~20 拍重发一次。
- `Policy.act` L4922-4923：`buyLand` 这一拍没出兵才轮到捐款，捐款发了这一拍就不再发船；在线每个决策拍只能进一条指令（L4797 的注释）。

**证据等级**：各桶的频率 E1（6 局录像真值）；日志侧的同一组模式在没看过的 23 局同版本对局里同样出现（损耗率 31.8% 对 32.4%），E2。「少捐这些就能多赢」E0：没有反事实；B021 收到的兵 65% 打了出去，照样输。

**反例与局限**
- B022 没有对倒、没有捐给空壳，损耗率照样 32%：截断占了大头（4 笔 280‰ 捐给密度 124~139 的 Eisenhower，少到账 439 万，其中 221 万随后回兵时溢出）。
- 「至多」是上限：收款人自己的利息也在花，窗口里的战斗耗兵不一定是捐来的兵。
- 日志侧「判为执行」靠捐款人余额读数，A / G 两组没有用录像核对过。
- 捐款有没有救活人没有量：没有「同样处境、没收到捐款」的对照组。
