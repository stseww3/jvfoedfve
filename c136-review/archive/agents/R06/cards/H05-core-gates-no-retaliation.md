# H05 核心期两道闸：有兵不出手，被打不还手（AT-worth-gate / EG-giant-neighbor-freeze / DF-passive-death / DF-main-attacker-unanswered）

**假设**：t≥1500 以后，一个号身边有真人可打、手里有兵，却连续几百拍不出兵，被真人打的时候也不还手。原因在 `buyLand` 的两道闸：地价闸（报价 ≥ worth 就整个 `break`）和保底线（`dpKeep` 超过余额就一兵不出）。这两道闸对「正在打我的人」几乎不放宽。

**定义**
- 真人报价的决策拍：影子策略这一拍 `offers` 里至少有一个真人邻居。对真人出了兵记「出兵」，否则记排第一的真人报价的出口行。
- 正被真人打：这一拍有外人真人的兵压在我身上。「不还手」= 这一拍没有对任何真人出兵。
- AT-worth-gate（日志侧）：密度 <100、一直有邻居，cmds / boats 计数连续 ≥450 拍不动。EG-giant-neighbor-freeze：同上但密度 ≥100。
- DF-passive-death（日志侧）：阵亡前 cmds / boats 连续 ≥450 拍不动，这段里有过邻居、领土在掉。
- 围攻（录像侧）：同一个外人对同一个我方号合计出兵 ≥20 万（相邻两条隔 900 拍以上拆开）；还手 = 目标在 [首条, 末条] 内对这个外人的出兵。

**脚本**：`scripts/coregates.py <局>`、`scripts/crossmatch.py gates|foes`；`scripts/foeprofile.py <局>`；`scripts/patterns.py count|hazard|overcap|deaths`。

**对照 / 效应**
- 超软上限且有邻居的快照，下一个间隔出手 对 不出手，之后 300 拍领土到过 1.1 倍的比例：mine 38.4% 对 9.5%（按局 15 比 0）；B·其余 40.4% 对 5.7%（20 比 0）；A 47.9% 对 18.8%（51 比 9）。之后 600 拍的坏结局（阵亡或领土跌到 75% 以下）：mine 25.0% 对 26.0%（7 比 8）；B·其余 21.7% 对 14.7%（9 比 12，p=0.66）；A 24.4% 对 11.8%（32 比 19，p=0.092）。出手能换到地是稳的；出手以后更危险还是更安全，没有结论。
- 有邻居而零指令 ≥450 拍，之后 600 拍的坏结局 对 发过指令的对照（按局 × 时段分层）：mine −2.4 个百分点（p=0.44）；B·其余 +1.7（p=0.54）；A +4.1（p=0.015）；G +2.1（p=0.75）。在 squad20 的两个分层里看不出「不出手 → 结局更坏」。
- 各局被打不还手的比例几乎一样（91%~98%），跟延迟（15~504 拍）、站位、人数都不相关：这是代码本身的性质，不是通道的问题。

**不是什么**
- 不是卡顿造成的：延迟正常的 B021 是 96.8%。
- 不是没兵：7 局里这些「不还手」的拍有 33% 卡在 `dpKeep`，那是「兵有，但留着」。
- 不是协防缺失：别的我方号同期打同一个外人的兵（1.09 亿）与目标自己的还手（1.07 亿）相当，B021、B017 最多；B038、B039、B010 几乎没有。

**代码位置**
- 报价：`offers` L5031-5036，`c = (rawNeed + fee) ÷ baseGain`，`rawNeed = elimCost(q) + 它压在我身上的兵 − 我压在它身上的兵`，`elimCost` L511-516 = `2×bal×(1 − x^1.6) + 2×terr×(1 − x)`，`x = min(1, (peak÷4) ÷ terr)`；`baseGain = max(1, terr − peak÷4 + (peak÷4)×0.1055×share)`。目标处在峰值领土时 `c ≈ 2 + 2.38×对方密度`。
- worth：`buyLand` L5258-5260，`m = maxW × winRatio(t)`（`maxW = 0.5`；`winT = [[1500,3],[2000,2.85],[2500,1.8]]` 线性插值），`refDens = max(自己密度, 0.85×其他真人密度中位)`（t≥2500），`worth = m × refDens`。t≥2500 时 `worth = 0.9 × refDens`。
- 地价闸：L5267 `if (c >= worth && c >= cheap && !over) break;`。t≥2500 时相当于「对方密度 < 0.38×我方密度」才放行。
- 对正在打我的人：L5103-5107 `c = min(c, defDisc × (elimCost − myAtk + fee) ÷ baseGain)`，`defDisc` = 0.88（t<4200 且没超软上限）或 0.85。放行线从 0.38 变成 0.44。
- 保底线：L5322 `safe = safeAt(g, q)`；对真人目标 = max(`safeFinite`, `dpKeep`)（`V17.safeAt` L2744-2754），只有目标快崩、在流血或 `tD < 0.45` 时才封到 88×领土（L5323-5326）；L5358-5361 `keep = max(keep, safe)`、`avail = B − fee − keep`、`avail <= 0` 就 `continue`。`dpKeep ≥ 0.988×B` 的条件是：最强真人邻居的兵（加上它压在我身上的）≥ 1.76×我的兵 + 1.5×我的领土。
- 超软上限以后（`over`）：L5348-5357 `keep = min(keep, overKeepMult×100×领土)`，`overKeepMult` = 0.9（一般）/ 1.12（唯一真人缓冲）/ 1.24（被围缩）/ 1.08（`crowdedHard`）；L5526-5528 买不起整笔时要求 `x >= 0.2×B`。换算成密度线：一般 114.2、唯一真人缓冲 128（L5271）和 142.1、被围缩 157.3（超过硬上限，到不了）。
- `holdOn = 0`：`hold` 不调用；c110 没有「被打就还手」的独立分支，还手只能走 `buyLand` 的报价。

**证据等级**：出口占比与不还手比例 E1（7 局）。日志侧的不出手时段在没看过的 23 局同版本对局里同样普遍（22/23 局），频率 E2。「超软上限时出手 → 领土涨」E2。「不出手 → 结局更坏」E0。

**反例与局限**
- 日志侧的 AT-worth-gate 只看「cmds / boats 不动」，分不清是卡在闸上还是真的没有合算的目标；只有 7 局影子策略能点到行号。
- B022 还手比例 48%、B021 24%，这两局照样输了：还手多不等于能赢，差距在总量和集中度（见 H12）。
- 报价的本意是「吃掉对方要花多少兵 ÷ 能拿多少地」。对一个密度比我高的邻居，吃掉它确实不合算；闸的问题在于它把「不合算吃掉」等同于「一兵不出」，没有守线或消耗对方进攻兵的选项。
- 影子策略每个决策拍只记排第一的真人报价的出口。
