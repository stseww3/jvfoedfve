## 8. 边界汇总：哪些能用，哪些不能用

前面各节的边界集中列在这里。左栏是模拟器的一种用法，右栏是这份验收给它的结论。

| 用法 | 结论 | 依据 |
|---|---|---|
| 只放录像，算某一局任意一拍的局面 | 可用，到「一队占满全图」为止。之后托管离场席位的内置 AI 与真引擎选得不同：A001 在 {{v:verify.tail.A001.t}} 拍之后、B023 在 {{v:verify.tail.B023.t}} 拍之后不用 | 第 2 节：{{v:verify.full}} / {{v:verify.n}} 局逐采样拍与真引擎相同，另外 2 局到终局之前相同 |
| 只放录像，算某一局的指令签名（实盘值） | 可用。与 `scripts/latency.py` 的输出没有逐数字交叉核对 | 第 3 节：重放与日志快照逐条相同的局才进区间；模拟值和实盘值由同一段账本代码算出 |
| 历史策略 + 这一局的实录阶梯（C2），重演 630 拍起的 900 拍 | 可用。指令签名在容差内的比例 {{v:ckpt.630.lag.C2.hitPc}}（卡顿的局）、{{v:ckpt.630.clean.C2.hitPc}}（不卡的局）；窗口末领土逐局偏离的中位见 6.2 | 第 5、6.2 节 |
| 同上，重演 1530 拍起的 1680 拍 | 签名可用（容差内 {{v:ckpt.1530.lag.C2.hitPc}}、{{v:ckpt.1530.clean.C2.hitPc}}）。窗口末领土不可用：只有 {{v:card.C2.1530.terrIn}} 局在 ±10% 内，而且偏向一边——真局里出了局的席位在模拟里活下来（{{v:revived.1530.n}} 个席位，反方向只有 {{v:revived.1530.lost}} 个），对手照录像不再打它，它就一直长 | 第 5.2、5.7 节 |
| 开环重演（对手照录像）的任何长窗口 | 同一条：我方席位只要比真局多活过出局那一拍，之后没有真人打它，领土偏高。窗口越长、真局里出局的席位越多，偏得越多 | 第 5.7 节 |
| 同一局、同一版历史策略，只换通道（C0 / C1 / C2），比窗口末领土 | 可用，限 900 拍上下的窗口；差要大于 6.2 节的噪声底才算数；是开环口径（对手不反应），偏乐观。1500 拍起的窗口另有两笔账：真局出了局的席位在不落后的臂里多活下来（占 C1 臂编队领土的 {{v:attr.dead.1500.lag.C1.share}} 上下），开环的前提也比 630 拍起的窗口弱 | 第 6 节 |
| 合成卡顿波（C3） | 只当「重度卡顿」的压力情形；量级比真卡顿局的中位重 | 第 4.4 节 |
| 实录阶梯在已知点之外的部分 | 已知点之间的补法对签名的影响见 4.3。最后一个已知点之后假定页面追平；录像在卡顿当中截断的局（B041，轻一些的 B025）这条假定不成立——日志里页面此后越落越远——模拟在这一段高估我方的出手（B041 的窗口末领土 ×{{v:hold.B041.630.def}}；把这一段的指令截掉是 ×{{v:cut.B041.630.terr}}）。这两局只到各席位最后一个已知点为止可信 | 第 4.3、5.7 节 |
| 闭环（对手模型），开局到 630 拍 | 统计上与录像对得上：对手和我方的人均地、兵密度的中位都在录像的 ±7% 以内 | 第 7.2 节 |
| 闭环，630~1071 拍 | 绝对量还对得上（中位在 ±5% 以内），相对量开始偏高：1071 拍我方人均地 ÷ 其余真人人均地是录像的 {{v:arena-cps.1071.rel}} 倍。只看方向，一成以内的差不读 | 第 7.2、7.7 节 |
| 闭环，1530 拍以后 | 不可用。历史策略自己放进去，我方人均地就已经是录像的 {{v:arena-cps.3210.sLand}} 倍（3210 拍）、{{v:arena-cps.4284.sLand}} 倍（4284 拍）；这一段里的领土、名次、存活、产兵都不是对实盘的估计 | 第 7.2、7.6 节 |
| 把「页面不落后」的通道（C1）下的读数当作实盘 | 不可以。有录像、进了区间的 {{v:live.cover.all.inBands}} 局里 {{v:live.cover.all.lag}} 局是卡顿局；卡顿局换成 C1，指令签名在容差内的只有 {{v:ckpt.630.lag.C1.hitPc}}，窗口末编队领土是真局的 {{v:attr.chain.630.lag.c1}} 倍 | 第 3.2、5.4、6.3 节 |
| 拿两条臂并排比（一版策略对另一版） | 没有验过，也不在本阶段的范围内。G0 验的只是「历史策略放回去能不能重现历史」；两条臂之间的差在模拟器里和在线上是不是一回事，没有任何一项检验碰过。闭环 1530 拍以后对手偏弱，这个偏差偏向哪一种打法，也没有量过 | 0.2 节 |
| 任何不在白名单里的策略 | `agents/R06/sim-v2/` 拒绝装载；本报告没有验过，也不对它作任何保证。联络分支 `c136-review/ci/sim-v2/` 那份副本去掉了白名单，不是本报告验收的东西（0.2 节第 5 条） | 第 1.6 节、0.2 节 |

另外几条和样本有关：

- **局数。** 入库 {{v:pack.n}} 局：Va {{v:pack.va.n}}、Vb {{v:pack.vb.n}}、Vc {{v:pack.vc.n}}、c110 {{v:pack.c110.n}}。不卡的局只有 {{v:pack.clean.n}} 局，Vc 只有 {{v:pack.vc.n}} 局。按版本、按卡顿档再分下去，每格常常只有几局，表里都写了局数；局数少的格只能看方向。
<!-- if: !(n('scope.va.runs') + n('scope.vc.runs') > 0) -->
- **Va、Vc 两版的断面重演这一版没有做。** 新接的 {{v:pack.ext}} 局只过了物理底座、实盘签名和实录阶梯；断面重演（第 5 节）、归因（第 6 节）和闭环（第 7 节）用的都只是核心 20 局（Vb {{v:pack.vb.n}} 局、c110 {{v:pack.c110.n}} 局）。
<!-- endif -->
- **选局。** 入库要求录像、日志、真引擎指纹、实录配对四样齐全。这样的局不是随机抽的：日志断得早的、录像缺的局进不来。第 3 节的实盘区间用的是全部有录像的局，没有这个问题。
- **结果量。** 归因一节的结果量是窗口末的编队领土。它不是名次，也不是胜负。
- **容差。** 「10 个百分点、同一量级」是会审提案里写下的讨论起点，没有经过会审确认。换一个容差，表里的命中数会变，逐局的原始数字（5.3 节）不变。
