# H07　后排被抽到三成密度后逐个被打穿，挨打时被判成弃子、没人救

> R04 假设卡｜来源：13 局复盘 + 全量对局包｜只写事实、机制和怎么证伪。

**陈述（可证伪）。** 封死的后排号只留 32~44×领土 的兵（Vb 的留底线）就把其余的调走；它们没有陆上敌邻，但对方的船和打穿前排之后的大号够得到它们。挨打的号一旦「压在身上的真人兵 > 1.65×自己的余额」就被从所有队友的调度候选里摘掉；能当捐款人的号又要求密度过线，被抽薄的后排号自己也救不了别人。结果是整队在一个短窗口里被逐个打掉。

**全量上的机械计数。** `scripts/bundle_patterns.py` 的 COLLAPSE（任意 600 拍窗口里出局的号 ≥ 一半）：123 局里 41 局；Va 6 局（46%）、Vb 30 局（51%）、Vc 1 局、g09 4 局、c110 0 局。squad10 赢的 8 局里 0 局，输的 67 局里 37 局（55%）。弃子判定本身要影子，全量上数不了。

**什么结果算证伪。** 弃子时段里即使把其余号高出 88×领土 的兵都送过去也顶不住（峰值的 21% 对进攻量本身就不够）——那「没人救」就不是出局的原因，而只是结果。现在的数只说明救援量几乎为零（2.5%），没有说明救了能不能活。

**混杂与边界。**

- 没有重放「有人救」或「后排不抽空」的情形。
- 配额解除后的集中供兵有两面：A022 判对（收款的 zero_7 领土 11,052→53,551，我方无一出局）；A047、A081、A083、A086 判不明——前线换到了地（A047 的收款号净得 21,441 格，A086 的净拿 18,488 格），但 A081 捐完的三个号密度只剩 22~41，A081、A086 的后排随后被逐个打穿（上面的 D24、D18）。
- 对面是不是有意挑刚捐完的号，录像里分不出来。
- COLLAPSE 是结局的形状，不只由这一组模式造成；c110 一局里有十几二十个号分在几支队里，这个口径对它难触发。

**要量的（模拟器 / 反事实断面）。** 对手要有「专挑密度低的后排号、一成余额一发」和「发船登陆后排」两种行为，否则复现不了这一组。在 4284 拍断面上量：后排留兵多少时，前线换到的地和后排丢的地相抵；弃子判定放宽后，被救的号多活多少拍、捐款人自己被打穿的次数。
