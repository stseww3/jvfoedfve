# H07 出生点：贴边、扎堆、最后一条指派没执行

- 现象的证据等级：**E2**（96 局真值落点；贴边 34% 对 23%；最近的真人是机器号 63% 对 13%；最后一条指派被执行的只有 55%）
- 「值多少地」的证据等级：**E1**——发现集里量不出它对 630 拍或 1500 拍人均对照的代价（相关都在噪声里）；看得见的只有它给留底互锁（H03）添的柴
- 对应模式：NEW-SP-01 / 02 / 03（只看日志的口径）、NEW-SP-05（最后一条指派没执行）、NEW-SP-07（各算各的槽位撞点）、NEW-SP-08（贴边排成一排）

## 一句话

编队的号出生得比野人更靠边、更挤，最近的真人十有六七是另一个机器号；选点阶段反复改派，最后一条指派落实的只有一半多。
但到 630 拍，人均地并不比野人少。出生点的代价在这批数据里量不出来；它留下的是「邻居都是自己人」，这正是 H03 那把锁的前提。

## 可证伪的陈述

1. own 落点贴边（离地图边 ≤ 短边的 12%）的比例高于同局野人；squad20 尤其高。
2. own 最近的真人是机器号的比例在六成上下；野人一成多。
3. 引擎落点等于日志里最后一条指派的席位只有一半多；squad20 只有四分之一。
4. 这些指标和 t=630、t=1500 的人均对照没有稳定的相关。

## 机制

- 策略侧（c110 `Policy.chooseSpawn` L4007-4154）：先向后端协调器要点（`window.__hlSpawnReq` → `window.__tsbAssignedSpawn`，日志 `[HL-SPAWN-BACKEND]`）；
  要不到就各号在自己的视图里排槽位（日志 `[HL-SPAWN]`）。各算各的时候，每个号看到的「已选队友」不一样，候选不够时按「离已选点最远」补位，会补到同一个点、或者一起补到图边。
- 两档走的是两条路：squad10 的指派 97% 来自后端协调器，squad20 只有 4%（基本是各算各的）。
- 选点阶段只有几十拍；每改派一次就要再发一条选点指令。引擎最后采用的常常是更早的那个点（squad20 有 72% 的席位如此）——是后面的指令晚到，还是根本没发出去，日志里分不清。
- 扎堆怎么变成 H03：`safeFinite` 取的是「AI 别的邻居里最弱的那个的余额」。邻居都是编队友、余额又相近，互锁就成立。

- 和 H06 的连接没找到：NORIG × CLUSTER -0.06，NORIG × EDGE -0.02，NADJ × CLUSTER -0.09。

## 反证和混杂

- 赢的局里 own 贴边比例中位 0.45，没赢的局 0.20（p=0.30）——贴边的局反而赢得多一点（不显著）。贴边可能有好处：背后没有敌人。
- 「最近的真人是机器号」在同一个房间里塞了两三支编队时几乎是必然的（人头占两到四成），不全是出生点算法的事。
- 自然地盘（Voronoi）只在我那 9 局算过，全量没有；全量只有贴边、最近邻这两个粗指标。量不出代价，也可能是指标太粗。
- squad20 的局大多录像不到 1500 拍（27 局里 13 局到了），分档结论的局数少。

## 交给验证集 / 模拟器

- E3：验证集上 own 贴边比例应高于野人至少 5 个百分点；最近的真人是机器号的应 ≥50%；最后一条指派被执行的应 ≤70%（squad20 ≤40%）。EDGE、CLUSTER × R1500 的秩相关若超出 ±0.3，这张卡「量不出代价」的结论要改。
- E4：模拟器里同一局同一批种子，只换编队的出生点（现状 / 强制散开到最近编队友 ≥ 野人的最近邻距离），看 t=630 的人均对照、600~1500 被 sb 挡住的占比、t=1500 的人均对照。
  预期：630 拍基本不动，被 sb 挡住的占比下降；1500 拍动多少，就是出生点通过 H03 值的地。
