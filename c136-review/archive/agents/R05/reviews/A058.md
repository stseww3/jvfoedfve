# A058 复盘（squad10，Vb，3 队，输；复盘员 R05）

## 一句话结论

这局不是打输的，是「没上场」：10 个号里 7 个客户端先后失联被标离线（785–1905 拍），剩下 3 个在 900–2300 拍一直落后服务器 130–500 拍，按几百拍前的局面下指令。策略一共发了 666 条指令，录像里只执行了 362 条（54%）。机器人的地被分完的那 600 拍（900–1500），全图 39.5% 的地换了主人，我方 10 个号只多拿了 1.0%。分型：**external**（次要 never-grew）。

策略侧有四个把损失放大的问题，都追到了代码行：① 开局「机器人锁」（留底被队友的存兵顶死）；② 指令不记在途、每 5 拍重发，落后时成批清仓；③ 调度不看配额、连发捐兵和互捐；④ 在线号被已离线队友的地围住后空转。

## 4. 三个转折窗口

**转折 1（900–1500）：机器人的地分完，我方没分到。** T1 15.2→25.9（第二→末位，落后榜首 2.0→9.0 个点）；编队 5.3→6.3。同期编队存兵 225k→1606k、密度 5.6→33.5（真人 9.5）——兵攒着没变成地。原因有两个，同时存在：

- *机器人锁（推断，影子策略）*。805–1405 七个采样拍，有相邻机器人的 51 个（号×拍）样本里，38 个没有任何机器人目标过得了留底（24 个留底 ≥ 全部存兵），其中 33 个的留底是队友定的。链路：`pickTarget` L1161 要求 可用兵 = 存兵 − 留底 > 0.2141×存兵；留底走 `floorFor0` L2235 → `winFloor` L4562–4569，其中一项 `safeFinite` = 相邻机器人「最弱的其它邻居」的存兵（`threatOf` L417–443）。两个我方号共用一个机器人邻居时，互相把对方锁住。例：sora_w 905 拍存兵 24293、留底 25781（经机器人#188，另一邻居是 noah88），五个每格 2.0–12.4 的机器人全被跳过。旁证：talon5 在 900–1530 每 90 拍只发 0–3 条指令，noah88 0–2 条。
- *发了不落地（观察）*。没被锁的号一直在发：alex_k 900–1080 发 34 条、落 0 条；riku_x 990–1260 发 45 条、落 0 条；sora_w 1260–1530 发 48 条、落 0 条。落地的那些也是旧决策：alex_k 1134 拍的九连发是它本地约 700 拍的决策（陈旧 430 拍），riku_x 1309 拍的六连发陈旧 509 拍。
