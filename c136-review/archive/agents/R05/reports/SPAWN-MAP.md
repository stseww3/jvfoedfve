# SPAWN-MAP — 选点代码地图 + 选点「真账」（R05 / M1）

口径：只写源码事实与可复算的数字，不含改动意见。源码（`c136-data/src/strategy/`）：协调器三版 `spawn-coordinator-c116-va.mjs`（A001–A017）、`-vb.mjs`（A018–A095）、`spawn-coordinator-c116.mjs`（Vc，A097–A099，1557 行；
行号默认指它，三版只差 1076–1077、1135–1136 四行和 Va 少的 1301 行）、`spawn-coordinator-c110.mjs`（B 系）；策略侧 `v27-team-c116.js` 的 `Policy.chooseSpawn`（3983–4129，三版相同）；引擎移植 `src/sim/sim/game.js`（530–704）。数字脚本见 §7。

## 1. 一句话流程

选点阶段每个号的浏览器每 ≥260 毫秒把「地图 + 全场真人当前位置」发给本机后台协调器（`window.__hlSpawnReq`，4003–4025）；协调器每次请求都**整队重算**一遍（`solve`），
把结果按号回填到 `window.__tsbAssignedSpawn`；号端发现点位变了就再发一条出生指令并打一行 `[HL-SPAWN-BACKEND]`（变化 >4 像素才打，4034–4037）。
后台结果没到时走「自主兜底」（4042–4126，打 `[HL-SPAWN]`）。引擎在选点阶段结束时以**每个号最后一条被执行的出生指令**为准；一条都没执行的号由引擎随机落点。

## 2. 引擎规则（`game.js`，引擎的逐行移植）

- 可选点对局开始时所有真人都没有地（538–543）。`chooseSpawn(x,y)` → `placeSpawnNear`（668）：从 (x,y) 起按方环 r=0..19 找第一个「可通行且 6×6 邻域内没有别人边界像素」的位置（`spawnAreaFree` 696），
  清掉该号旧出生块，放一个 4×4 去四角的 12 像素出生块（`claimSpawn` 606）。**所以两个号点同一个像素不会被拒，后到的会被挤到紧挨着的空位——两人从第 0 拍起贴脸。**
- `endSpawnPhase`（657）：选点阶段结束时**没有地的真人由 `findSpawnCell` 随机落点**（10 像素网格，565）。
- 录像里出生指令是 id=0，参数 = 像素下标 `y×W + x`（`c102-replay-lib.mjs` 190–191）。选点阶段长度（步）：真人 ≤2 → 31，≤50 → 41，否则 51。

## 3. 协调器 `TeamSpawnCoordinator.solve`

**尺度**（837–853）：`rCell = sqrt(max(10000, land) / (π × N))`，`N = max(8, 已落点的敌人 + 已落点的路人队友 + boss + 我方号数 K)`。
注意 N 只数**已经点了位置（terr>0）的真人**（827–834），所以选点阶段里随着别人陆续落点，`rCell` 不断变小，整套半径跟着缩——这是阵型在选点阶段不停「呼吸」和换位的直接原因。
`allyMinSep = clamp(round(1.48 rCell), 72, 118)`；`enemyMinClearance = clamp(round(0.70 rCell), 36, 78)`；`clusterMax = clamp(round(3.35 rCell), 190, 320)`；
`bossExcl = clamp(round(max(1.12 rCell, 0.078 对角线)), 68, 120)`；`flankMax = clamp(round(max(2.30 rCell, 0.170 对角线)), 135, 235)`。

**A. 角落扇形阵（Corner Sector Phalanx，1064–1282；条件：没有 boss 且 K ≥ 6 → A 系 10 人编队走这条）**
1. 半径（1074–1077）：`minReqSep = clamp(round(0.95 rCell), 42, 68)`；`r0 = clamp(round(0.48 rCell), 28, 46)`；`clamp` 下界优先（67 行）。三版只有 r1/r2 的系数与夹值不同：

   | 版本 | r1（内弧） | r2（外墙） | 扇形半角 | 内弧号个数（K=10） |
   |---|---|---|---|---|
   | Va | clamp(round(1.38 rCell), max(78, r0+minReqSep), 132) | clamp(round(2.35 rCell), max(142, r1+minReqSep), 225) | π/3.2（56.25°） | min(3, max(2, floor((K−1)×0.34))) = 3 |
   | Vb | clamp(round(1.12 rCell), max(66, r0+minReqSep), 108) | clamp(round(1.88 rCell), max(122, r1+minReqSep), 182) | π/3.2 | 同 Va = 3 |
   | Vc | clamp(round(1.32 rCell), max(76, r0+minReqSep), 126) | clamp(round(2.28 rCell), max(145, r1+minReqSep), 220) | π/2.55（70.6°） | min(2, max(1, floor((K−1)×0.22))) = 1 |

   **下界 `r0+minReqSep`（≈1.43 rCell）与 `r1+minReqSep`（≈2.38 rCell）在常见密度下压过系数**：按公式代入，rCell=60–70 时三版给出**完全相同**的 r1/r2（60 → 86/143、65 → 93/155、70 → 100/166）；
   只有 rCell<55（人多的局：Vb r2=122–132，Va 142，Vc 145）和 rCell>75（人少或选点早期：Va 188–225，Vb 172–182，Vc 172–220）才分开。A 系有录像的局里按全场真人数代入：Vb 55 局中 rCell 在 55–75 的 28 局、<55 的 18 局、>75 的 9 局。
2. 四个角（距边 24 像素，1078–1083）各自找「角锚点」：在距角 0.42×min(W,H) 的方形范围内以 16 像素步长扫描，只取**最大陆块**上的点，
   周围 `min(280, r2)` 半径内同陆块采样点数 `landSamples ≥ 14`，评分 `landSamples×18 − 到角距离×2.2`（1093–1131）；扇形中轴 = 采样到的陆地方向平均值。
3. 角色与个数（1135–1170）：`CORNER_APEX_BANK` ×1：中轴上 r0 处（最靠角里）；`INNER_ARC_BANK` × 内弧个数：r1 弧上，张角 ±0.82×半角；
   `OUTER_SHIELD_WALL` × `K−1−内弧个数`：r2 弧上，张角 ±半角，等角分布。即 Va/Vb 是 1+3+6，Vc 是 1+1+8。
4. 落点吸附（1172–1206）：每个理想点按半径系数 [1.0, 0.88, 1.12, 0.76, 1.24, 0.64, 0.52] × 角度偏移 [0, ±0.10, ±0.20, ±0.32, ±0.45] 依次试，吸附到最近陆地（同陆块），
   且与**已选的我方点**相距 ≥ `minReqSep`；失败再沿中轴 ±0.85 弧度逐圈找；仍不足 K 个则在 r2 附近补 `OUTER_SHIELD_WALL`（1224–1255）。
   **点位选择只对我方点做间距检查，不对敌人位置做任何避让**；敌人只进入「选哪个角」的评分。
5. 选角评分（1262–1268）：`点数×900 + 锚点评分×3.5 + Σmin(240, 各点到最近敌人距离)×1.2 + min(200, 最小敌距)×2.5 − 扇形内(r2+45)敌人数×220 − 锚点到角距离×1.5`。
   **本局第一次解出的角被锁定**（`lockedCornerName`，1084–1090、1276）：之后敌人再怎么落点，都只在这个角里重算。
6. 输出字段固定 `voronoiPixels: 5000`、`bossDist: −1`（1218–1219）——日志里 `voronoi=5000 bossDist=-1` 就是走了扇形阵的标志。

**B. 其它路径**（有 boss，或 K<6，或扇形阵凑不够 max(6, K−2) 个点）：`FLANK_GUARD`（有 boss 时 K≥5 → 2 个，K≥2 → 1 个）+ `ECO_BANK`，
逐个 `pickNextTarget`（938）：按放宽系数 [1.0, 0.80, 0.62, 0.42] 逐轮放宽「与我方最小间距 / 与敌人最小净距 / 离簇最大距离」，
候选点用 `evaluateCandidate`（约 590–780）打分：对候选点做 BFS 维诺盆地（最大步 112），盆地像素 < `min(1200, 0.006×land)` 淘汰；还有被夹击惩罚 `computePinchMetrics`、海岸/焊接加分等。这条路径**有**敌人净距约束。

**C. 号与点的匹配**（`matchBotsToTargets` 1431）：K=M≤12 时用位掩码 DP 求「总位移最小」的一一匹配，参考位置 = 号当前领土中心（已落点）或上次指派点；
新点与上次指派相距 ≤6 像素则保持旧点（1360–1368）。单次求解内每个号拿到的点互不相同。
**D. 服务**（1496–1556）：HTTP，`POST /solve`（带地图则先 `setMap`），`GET /status|/plan`。

## 4. 策略侧 `Policy.chooseSpawn`（3983–4129）

- 槽位 `slot = __tsbSquadSlot % 10`（3995；c110 是 % 20）；`squadIds` = 自己 + 名字在白名单里的号（3987–3991）——`[HL-SPAWN] (squad=N,…)` 的 N 就是它，等于该号在**自己这一盘**里看到的自家号数（拆盘检测用）。
- 有 `__tsbAssignedSpawn` 且地图尺寸对得上 → 直接返回后台点（4027–4039）。
- 兜底：把其它自家号从局面里抹掉后算 `spawnVsPeople` 候选（每 2.2 秒最多重算一次，4051–4062），按 `minSep = max(96, min(175, 0.14×对角线))`（c110：max(85, min(145, …))）贪心挑出互相不挤的点，取第 `slot` 个（4064–4093）。
  各号各算各的、候选表又随时间变，所以 B 系（纯兜底）拿到同一个点的概率不低（见 §5）。
- c110 的协调器没有扇形阵；`allyMinSep = clamp(round(max(1.15 rCell, 0.068 对角线)), 64, 110)`，`clusterMax = clamp(…, 220, 460)`，锚点陆块要求 ≥ max(25000, 0.45×最大陆块)。

## 5. 选点真账：日志指派 vs 录像里真正执行的出生指令（`spawn_truth.mjs` → `out/spawn-truth.tsv`）

方法：录像出生指令像素 = `y×W+x`，W 未知 → 枚举 W 使我方出生像素解出的坐标落在日志指派点集合里的条数最多（A058：W=1900，292/292 条全中）；再用 W 解出全场真人最终出生点。

全量（有录像的包）：
- **squad10：75 局，解出 W 的 70 局里，19 局（27%）至少有一对我方号最终出生在同一个像素**（叠点；A021、A031、A083 各 2 对，A050 一个点上叠了 3 个号）；
  42 局至少有 1 个号「日志最后一条指派」没有被执行；只有 28 局全部一致。
- **8 局有号一条出生指令都没被执行（= 引擎随机落点）**：A001（2 个号）、A002（6）、A003（7）、A017（录像里唯一的号）、**A026（9 个号里 8 个）**、A070（10/10）、A073（2/2）、A081（4）。

## 6. 实测几何 vs 各版公式（`spawn_rings.mjs` → `out/spawn-rings.tsv`）

- 角色个数：Va/Vb 的局是 角尖 1 + 内弧 3 + 外墙 6（Vb 有角尖号的 51 局里 36 局内弧 3 个；包里只有 9 个号的局是 1+3+5，说明协调器名册仍是 10 个）；Vc（A097–A099）是 1+1+8。与三版源码的个数公式一致。
- 以「到角尖号的距离」做区间检验（各版用自己的公式、全场真人数代入、±12 像素余量）：内弧号落在区间内 Va 20/23、Vb 140/143、Vc 3/3；外墙号 Va 40/48、Vb 235/284、Vc 24/24。
  外墙号偏出的主要原因是吸附时换用了 0.52–1.24 倍半径（§3-A-4）以及执行到的是早一轮（rCell 更大）的解。
- 相邻我方号最近距离中位数：A014 53、A058 59、A037 71、A034 75、A065 79、A095 49（像素）；即每个号开局能独占的圆半径约 25–40 像素。
