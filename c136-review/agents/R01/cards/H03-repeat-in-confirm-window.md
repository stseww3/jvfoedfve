# H03 正常延迟内对同一目标重复下令，首击被叠成几倍

把握：中（现象全量可数；净亏只在 A003 等几局逐组核过）。相关模式：`IO04`（8 局，7 错 3 不清）。

## 假设

通道正常时也有一种多扣：上一条令还在路上（7–19 拍），策略看到的局面没变，下一个决策拍又对同一个目标下同样的令。引擎把后到的令加到已有的进攻上，本意出一份兵，实际出了两三份，打完余额低于自己的保底线，随后被反推。

## 机制

- 决策周期 5 拍，落地延迟正常是 7–19 拍，一条令落地前有 1–3 个决策拍。
- 预算分支 `Policy.buyLand` L5611–5616 和脉冲分支 L5594–5607 按当拍余额和线上兵算出兵额，不记在途的令；1500 拍前 `Style.pickTarget` L1162 的 need 只减已经在线上的兵（`g.attackTroopsOn(me, q)`）。
- 引擎：已经在打同一目标时，新令不需要建线，直接付费、加兵（`game.js attack` L1271、L1280–1282）。
- `Policy.updateShadowQuota` L3821–3834 的核对同样不知道令还在路上（见 H09）。

## 证据

- 15 局，落地拍在 600–1500 的陆攻里，21 拍内对同一目标重复的 384 条（13%）。最多的是通道干净的局：A019 71、A055 69、A023 64、A054 45；掉队的局反而少（A009 0、A057 2、A059 3），因为它们的令隔很久才到。
- A003：1500 拍后 41 个重复组，实扣 ÷ 本意的中位 2.78，首击被叠到余额的五到七成；riku_x、talon5、ryan_m 打完余额低于自己的保底线，35–77 拍后被目标的同队反推。
- 全量：squad10 本队 21 拍内对同一目标同一比例重复落地 3433 条，占本队落地陆攻的 9.2%；squad20 283 条（2.7%）。

## 怎么数

```bash
python3 scripts/m6_all_replay.py          # replay_facts.csv：repeats、atkLanded
python3 scripts/strike_reply.py <局>      # 每一轮打真人：实扣/本意、打前打后密度、第一条打回来的令隔几拍
python3 scripts/shadow_report.py <局> --section repeat
```

## 什么结果算证伪

- 重复组的实扣 ÷ 本意中位接近 1（那样重复的令大多一兵未扣，没有叠加）。
- 重复组打完以后被反推的比例不高于单条首击（用 `strike_reply.py` 末尾的基线比）。

## 没弄清的

- 重复下令在对 AI 地时多半无害（多出的兵打完流回余额），净亏集中在对真人的首击；全量表没有把两类分开。
- 重复有时是有意的加码（对方在增援时）。全量计数分不出有意和无意，A009、A050、A005 的 3 条判“不清”。
