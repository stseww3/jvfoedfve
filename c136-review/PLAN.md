# c136 复盘提升项目：分析与落实方案

> 状态：**v0.1 待管理员审定** ｜ 牵头与对接人：`c136` ｜ 参与：10 个同型号模型 `R01 ~ R10`
> 范围：组队模式小队策略（`v27-team` 系，10 人队 / 20 人队）的 **分析 → 验证 → 落实** 流程。
> 本文只规定「怎么分析、怎么验证、怎么落地」，**不预设任何具体策略改动**。进房、代理、协议层不在范围内，项目期间保持不动（它们一变，对局数据就不可比）。

## 0. 一页结论

1. **数据比想象的少，而且大部分还不在 GitHub 上。** 组队模式累计大约 150~250 局量级，我能亲手核实的只有 9 局自动局加几份录像；其余都在本地 d3（见 §1）。
2. **上一轮十路分析没有带来提升，问题出在方法，不在努力程度**（见 §2）：9 局样本、每个模型读 1 局写「主因权重」再取平均、没有对照实验、对局环境没控制、版本边打边改。
3. **这一轮靠 5 个机制保证结论是真的：**
   - **a. 先有可重放的全量真相。** 每局用游戏引擎重放录像，拿到全场所有玩家逐拍数据；所有数字必须出自提交进仓库的脚本。
   - **b. 提假设的人不验证自己的假设。** 对局切成发现集 / 验证集 / 封存集，分析员只看发现集。
   - **c. 四层分辨率两头对账。** 总体 → 阶段 → 逐拍 → 代码；每条结论既要有「多少局出现、值多少胜率」，也要有「哪局哪拍哪行代码」。
   - **d. 证据分级 E0~E5。** 通过反事实配对实验（E4）才能进新版，通过实盘交替 A/B（E5）才能上线。
   - **e. 红队否决 + 稳健性矩阵。** 平均更强不够，任何一类对局都不许明显变差。
4. **10 个模型按职能分工，不按「一人一局」分工**（见 §5）：4 个搭地基（数据、裁判、复盘引擎、模拟器），4 个做专题分析，1 个研究赢家和对手，1 个专职挑错。
5. **需要你拍板 5 件事**（见 §11），其中最急的是：把 d3 上的对局数据导出来。

## 3. 总体流程：6 个阶段，4 道闸门

```
阶段0 地基 ──G0──> 阶段1 广谱分析 ──G1──> 阶段2 独立验证 ─> 阶段3 改动卡
                                                              │
        阶段6 循环 <──G3── 阶段5 实盘交替A/B <──G2── 阶段4 候选版集成
```

每道闸门是一页报告，发给管理员；G0、G2、G3 需要管理员点头才往下走。

### 阶段 0：地基

| 编号 | 做什么 | 负责 | 产出 |
| :-: | :-- | :-: | :-- |
| 0.1 | **数据冻结与入库。** d3 上的结算、日志、录像只读导出到数据分支；每局一条清单记录（时间、哪支小队、人数、策略版本、游戏版本、队伍数、房间真人数、地图、结果、数据完整度、污染标记）；每局一张 ≤ 2 KB 的对局卡和一张逐号轨迹表 | R01 | `manifest.jsonl`、对局卡、数据质量报告 |
| 0.2 | **切分。** 按时间块分层随机：发现集 60% / 验证集 25% / 封存集 15%；名单提交后不再改动；验证集和封存集放单独的封存分支 | R01 + R02 | 切分名单 |
| 0.3 | **度量体系。** 主指标：分层胜率（队伍数 × 房间规模 × 小队人数）和超额胜率（实际 − 基础期望）。过程指标：t=600 / 1500 / 3000 的团队领土份额与排名、存活曲线、利息收入对税费损耗、捐款净效率、领先转化率、被翻盘率。每个过程指标先证明它能预测胜负再使用 | R02 | 指标定义、基线表、功效表 |
| 0.4 | **胜率曲线。** 局面 → 获胜概率的简单模型（少量特征、交叉验证、校准），把每局的一个胜负变成一条曲线，用来定位「胜率掉得最多的窗口」 | R02 | 模型 + 校准图 |
| 0.5 | **机制规格书。** 利息、攻击损耗、各类税费、捐款、船：公式从引擎代码里取，配单元测试，之后所有分析以它为准 | R06 + R03 | 规格书 + 测试 |
| 0.6 | **复盘引擎。** 用游戏引擎无头重放录像，输出全场所有玩家逐拍真相（重放终局必须和结算记录一致）；关键窗口切片；分叉重放（从真实局面第 T 拍换上另一版策略，短窗口内推演） | R03 | 重放器、切片器、分叉器 |
| 0.7 | **模拟器校准。** 组队模拟器对齐实盘：开局领土曲线、利息与税费、对手行为分布的差距报告；从录像提取多种风格的对手池；配对实验规范 | R04 | 差距报告、对手池、实验跑道 |
| 0.8 | **采集纪律（即刻生效）。** 每局必存完整录像；结算记录带策略文件哈希；两支小队不进同一个房间 | c110 / c116 执行，R01 验收 | — |

**闸门 G0：《基线报告》。** 真实数据量与质量、各分层的基线胜率和置信区间、哪些过程指标有预测力、模拟器在哪些方面可信。管理员据此确认验收线（§11 第 2 项）。

### 阶段 1：广谱分析（只用发现集）

四层分辨率，自上而下定方向，自下而上找原因：

| 层 | 问题 | 方法 | 产出 |
| :-: | :-- | :-- | :-- |
| L0 总体 | 输的局都是怎么输的，各占多少 | 输局分型（开局夭折 / 始终没长大 / 中盘崩盘 / 领先被翻 / 外部因素），份额加起来 100% | 分型表，决定力气往哪花 |
| L1 阶段 | 每局在哪个阶段丢的胜率 | 胜率曲线分段，找最大跌幅窗口 | 每局的关键窗口清单 |
| L2 逐拍 | 关键窗口里哪些决策错了，错多少 | 全量真相 + 分叉重放，给出每个决策的损失估计 | 决策审计表 |
| L3 代码 | 错误决策由哪段逻辑、哪个参数产生 | 日志原句 ↔ 源码行 | 代码定位 |

另外两条并行线：

- **赢家对照（R09）：** 同一批录像里，赢的队和排名靠前的真人做了哪些我们没做的事。c110 对 c116 当作一组自然实验来读，先扣掉人数和房间差异。
- **异常扫描（R01 / R03）：** 机械检测器全量扫，不靠人眼。例如指令被拒、余额异常跳变、延迟尖峰、输血方向倒挂、同拍连环转捐。

每条发现写成一张假设卡（模板见 §6）进台账。**本轮假设卡提交之前，分析员互不看对方的结论**，提交后由 c136 合并去重。

**闸门 G1：《假设台账 v1》。** 按「出现频率 × 单次代价」排序，每条标明证据等级。

### 阶段 2：独立验证

- **E2 → E3 复现：** R02 用分析员提交并冻结的检测脚本在验证集上重跑。方向一致、效应量落在发现集的区间内才算复现。
- **E3 → E4 反事实：** R03（分叉重放）和 R04（模拟器配对）回答「修掉它值多少」。指标和最小效应事先登记。
- **红队（R10）：** 对每条 E3 以上的假设写反方意见：有没有混杂、是不是只在某一类对局成立、修了以后在什么局面会变差。

### 阶段 3：改动卡

- 一条 E3 以上的假设对应一张改动卡：最小代码改动，带独立开关，默认关闭。
- **单因子消融：** 只开这一项对基线，配对实验。
- **减一检验：** 全部开启后逐项关掉，查交互。
- **常数类改动做敏感性扫描：** 最优值上下 ±20% 仍优于基线才收（平台型）；只在一个点上好的不收（尖峰型，过拟合的典型形状）。
- 优先级：修 bug 和逻辑矛盾 > 由机制推出的规则 > 调常数。
- 复杂度预算：每加一条规则都要有 E4 证据；同时清理被证明无效的旧规则。

### 阶段 4：候选版集成

- 通过的改动卡合成候选版。
- **稳健性矩阵：** 队伍数（2 / 3 / 4 以上）× 房间规模 × 出生类型（主大陆 / 次大陆 / 岛）× 小队人数 × 对手风格。规则：总体显著更强，并且没有任何一格显著变差。
- **终检：** 留出的地图、种子、对手和封存集的分叉重放，只跑一次，不许回头再调。
- 红队总攻。

**闸门 G2：《候选版离线成绩单》。**

### 阶段 5：实盘交替 A/B

- 同一支小队、同一批号、同一时段，基线版和候选版按局交替；测量期间不热更新；每局结算带版本哈希。
- 事先登记主指标、判定规则（后验概率 P(新 > 旧) ≥ 95% 判胜，≤ 5% 判负，设最大局数）、次指标。
- 样本量见 §7。

**闸门 G3：上线或回滚。**

### 阶段 6：循环

新对局持续入库；上一轮的封存集并入发现集，新打的局成为新的封存集。

## 4. 三类风险的对应机制

| 风险 | 机制 |
| :-- | :-- |
| **过拟合** | ① 发现集 / 验证集 / 封存集，按时间切分 ② 假设和检测脚本先登记、冻结，再验证 ③ 提出者 ≠ 验证者 ④ 反事实实验用没见过的地图、种子、对手 ⑤ 常数必须是平台型 ⑥ 台账记录总共检验了多少条假设，按数量收紧显著性要求 ⑦ 任何分层不许变差 ⑧ 封存集只用一次 ⑨ 实盘 A/B 事先登记停止规则 ⑩ 红队有否决权 |
| **过粗** | ① 胜负按队伍数、房间规模、小队人数分层 ② 胜率曲线把一个胜负拆成整局的轨迹 ③ 输局分型，份额加起来 100% ④ 指标落到每个号、每种角色（前线 / 后排），不只看团队总量 ⑤ 决策级损失估计，而不只是结局 |
| **漏细节** | ① 关键窗口逐拍审计，用全量真相而不是我方日志的视角 ② 机制规格书和单元测试，策略里的公式逐条对引擎 ③ 机械异常扫描全量覆盖 ④ 每条发现必须同时有频率、代价、实例清单、代码位置、检测脚本 ⑤ 抽样复算：另一个模型从原始数据重算一遍数字 ⑥ 解释不了的现象记入「未解清单」，不许略过 |
| **模型自身的毛病**（编数字、讲故事、过度自信） | ① 没有脚本的数字不收 ② 报告是结构化的假设卡，不是长文 ③ 「根因」「根治」只允许用于 E4 以上 ④ 任务卡小步、每步提交 |

## 6. 证据分级与假设卡

| 等级 | 含义 | 可以做什么 |
| :-: | :-- | :-- |
| E0 | 猜想，没有数据 | 进台账备查 |
| E1 | 个例：至少 1 局，有局号、拍号、日志或代码出处 | 继续查 |
| E2 | 规律：检测脚本在发现集上给出频率和效应量，带置信区间，分层后仍成立 | 送去验证 |
| E3 | 复现：冻结的脚本在验证集上由裁判重跑，方向和大小一致 | 写改动卡 |
| E4 | 反事实：配对实验，置信区间不含 0，没有分层倒退 | 进候选版 |
| E5 | 实盘：交替 A/B 达到事先登记的判定线 | 上线 |

假设卡必填项：

```
编号 / 提出者 / 当前等级
一句话陈述（可被证伪，带数字）
检测规则（脚本路径 + 冻结的提交号）
频率：在多少局中出现（分层列出）
代价：出现时胜率曲线或过程指标掉多少（带置信区间）
实例：局号 + 拍号，至少 5 个，含 1 个反例

预期改动方向（不写具体参数值）
```

## 7. 实验与统计规范

**实盘 A/B 需要多少局**（双侧 5% 显著性，80% 把握）：

| 想证明的提升 | 每臂需要 |
| :-- | :-: |
| 13.5% → 40% | 约 45 局 |
| 13.5% → 30% | 约 100 局 |
| 66% → 80% | 约 160 局 |
| 66% → 71% | 约 1350 局 |

- 目前单队大约每小时 7 局（c116 白天 11 小时 81 局）。实盘只能确认大幅度的提升，小幅度的改进必须靠离线配对实验和过程指标来分辨。**所以离线评估能力是这个项目的放大器**：有了可信的重放和模拟器，10 个模型一天能检验上百个想法，而不是热更新上线后等一天看七十局。
- 离线配对实验：同图、同种子、同出生点、同对手，候选版对基线，每臂 300 配对局起步，具体数量由 R02 按登记的最小效应计算。重型模拟走 GitHub Actions，不在 VM 上跑。
- 现行的 36 局/臂门禁太小：8/36 对 13/36 这样的差别不显著，不能用来下结论。
- 报告一律给出效应量和置信区间，不只给 p 值或「显著」二字。
