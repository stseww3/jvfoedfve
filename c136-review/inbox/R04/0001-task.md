# R04 任务卡：引擎机制 B（组队、捐款、海战、内置 AI、出生、胜负、录像格式）

管理员原话：「对游戏代码理解也要nextlevel」。R03 负责经济和战斗核心，你负责其余和组队对局直接相关的规则。上一轮同一个捐款税出现过 10% 和 6.25% 两个数字，这类问题要在你这里终结。

## 输入

- 游戏客户端代码：数据 B 的 `tsb/squad/live_game_js.js`（压缩混淆过，约 680 KB）和 `live_dictionary.json`（部分变量名对照）。**用脚本定位和抽取片段，不要整段读进上下文。**
- 已有的理解：数据 C 的 `territorial-sim/sim/`（模拟器源码）、`NOTES-c6.md`、`NOTES-c22-ocean.md`（海洋机制）、`tools/` 里读录像的工具；数据 D 的 `tools/c117/teamgate.mjs`（模拟器的组队模式和捐款记账）。先读这些。
- 实测数据：数据 A 的小队日志和结算记录；5 份组队录像。

## 要回答的问题

1. **组队规则：** 队伍怎么划分；队友之间能不能互相进攻、边界怎么处理；队友的领土算不算邻居；一局有几支队由什么决定。
2. **捐款：** 能捐给谁、有没有条件；一次捐多少（比例参数的含义）；手续费或损耗是多少、扣在谁身上；有没有冷却或频率限制；到账是即时的还是有延迟。
3. **船与海战：** 发船的成本和条件；航行速度；登陆怎么结算；两条船相遇或拦截怎么结算；旧报告说船扣 3.125%，请核实。
4. **内置 AI：** 游戏自带的机器人什么时候进攻、怎么选目标、兵力怎么留；有没有投降或被接管的状态；难度有没有区别。
5. **出生阶段：** 选点的规则、时长、有没有保护期；出生后初始领土和兵力。
6. **胜负判定：** 组队局什么时候结束；结算记录里 `won`、`lost`、`over` 分别对应什么条件（客户端判定的部分；我方编排脚本的判定由 R06 负责）。
7. **录像数据格式：** 录像里记录了什么、怎么编码，够不够重放出全场状态。配合 R02。
8. **地图：** 大陆和岛屿在数据上怎么表示；陆地像素总数的含义。

## 交付格式

`reports/MECHANICS-B.md`，每条规则一节：

```
规则名
出处：代码里的定位方式（函数特征串或偏移），以及模拟器里对应的实现位置
公式或规则：精确写出
置信度：高 / 中 / 低，依据是什么
和模拟器实现的差异：有就写，没有写「一致」
可检验的预测：给一个能用日志或全量真相核对的数字
```
