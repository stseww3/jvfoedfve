# R03 任务卡：引擎机制 A（经济与战斗）

管理员原话：「对游戏代码理解也要nextlevel」。上一轮的分析里，同一个机制出现过互相矛盾的数字，说明没人对着引擎逐条核实过。你负责把经济和战斗这两块核实到可以写成单元测试的程度。

## 输入

- 游戏客户端代码：数据 B 的 `tsb/squad/live_game_js.js`（压缩混淆过，约 680 KB）和 `live_dictionary.json`（部分变量名对照）。**用脚本定位和抽取片段，不要整段读进上下文。**
- 已有的理解：数据 C 的 `territorial-sim/sim/`（模拟器源码本身就是一份机制实现）、`NOTES-c6.md`、`NOTES-c22-ocean.md`、`tools/oracle.js`、`tools/clone-test.js`、`tools/rng-trace.js`。先读这些，不要从零开始。
- 实测数据：数据 A 的小队日志，`[HL-TICK]` 每 90 拍记录一次每个号的领土、兵力、密度。

## 要回答的问题

1. **时间：** 一拍多长；收入和利息多久结算一次。
2. **经济：** 兵力增长的精确公式。利息率怎样随时间、领土、密度变化；上限在哪；「密度到 100 附近边际利息为负」这个说法是否属实，精确形式是什么；领土本身有没有收入。
3. **进攻：** 发兵指令的参数含义（比例的分母、最小值）；发兵时有没有即时扣除的费用，是多少（旧报告说陆地进攻扣 1.17%，请核实）；打中立地和打玩家各自怎么结算（每格成本、防守方怎么损耗、推进顺序和速度）；同时多路进攻怎么分配；兵力不够时会怎样；能不能撤回。
4. **防守：** 被打的一方兵力怎么损耗；领土被吃掉时兵力怎么变。
5. **淘汰：** 玩家死亡的条件；死后领土和兵力的去向。
6. **数值细节：** 整数运算、舍入方向、溢出和上限。

## 交付格式

`reports/MECHANICS-A.md`，每条规则一节：

```
规则名
出处：代码里的定位方式（函数特征串或偏移），以及模拟器里对应的实现位置
公式或规则：精确写出
置信度：高 / 中 / 低，依据是什么
和模拟器实现的差异：有就写，没有写「一致」
可检验的预测：给一个能用日志或全量真相核对的数字
```

**M3：数值核对。** 用小队日志里没有出兵的窗口，核对兵力增长是否符合你写的公式；写成脚本，输出误差。
