# R02 任务卡：录像重放与全量真相

我方日志只有我方 8~20 个号的视角。要看清对手什么时候、用多大兵力打的我们，需要用录像重放出全场所有玩家的数据。这是你的任务。

## 输入

- 组队录像 5 份：数据 A 的 `c116-winrate/replays/`（4 份）和数据 B 的 `tsb/squad/latest-replay.txt`。
- 游戏客户端代码：数据 B 的 `tsb/squad/live_game_js.js` 和 `live_dictionary.json`。
- 现成工具：数据 C 的 `territorial-sim/tools/`，例如 `replay-read.mjs`、`replay-dump.mjs`、`replay-map.mjs`、`c102-replay-lib.mjs`、`c102-replay-dissect.mjs`、`pure-node-dissect.mjs`、`c58-dissect-batch.mjs`、`people.mjs`、`timeline.mjs`。它们是给单人局写的。

## 里程碑

**M1：摸清现有工具。** 每个工具的输入、输出、依赖（要不要浏览器）、是否支持组队局、对应哪个游戏版本。产出 `reports/REPLAY-TOOLING.md`：能力矩阵和缺口。

**M2：跑通一份组队录像。**

1. 先量资源：单份录像重放的耗时和内存。`timeout 120` 内跑不完或内存超过 1 GB，就不要在 VM 上硬跑，改成设计 GitHub Actions 批处理并在 `report` 里报预算。
2. 输出 `truth/`：
   - `teams.csv`：拍、队伍、领土、兵力、存活人数
   - `players.csv`：拍、玩家、队伍、领土、兵力、是否存活（采样间隔你定，建议不大于 30 拍）
   - `attacks.csv`：拍、发起方、目标、兵力（能从录像指令里得到多少给多少）
   - `deaths.csv`：拍、玩家、被谁吃掉
3. **校验：** 重放的终局必须和已知结果一致。例如 `mw80pf` 这一局已知全图陆地 773,207、`zexos1` 第 1 名 374,245 地。对不上就说明重放不可信，先查原因，不要往下做。

**M3：5 份录像全部产出 `truth/`**，发布到 `c136-review/agents/R02/out/truth/<对局编号或录像名>/`，写清楚每份和哪一局对应（和 R01 的对局编号对接通过我）。

**M4：关键窗口切片器。** 输入对局、起止拍、我方某个号；输出窗口内这个号和它所有邻居的领土、兵力、出兵序列。复盘员审计转折点时用。

**M5（新数据到达后）：批量重放。** 我会告诉你新录像的位置。

**M6（后期）：分叉重放可行性。** 从真实局面第 T 拍换上另一版策略推演一小段，需要什么、难点在哪。只评估，先不做。

## 验收

- `truth/` 的每个数字能由脚本从录像重新生成。
- 校验结果写在 `reports/REPLAY-VALIDATION.md`：每份录像重放终局和结算记录的逐项对比。
- 说不清的字段（例如某个量到底是兵力还是别的）标「待核实」，把问题发给我，我转给 R03、R04。

## 范围

只做对局数据的重放。客户端代码里和连接握手、验证、代理有关的部分不看、不改。
