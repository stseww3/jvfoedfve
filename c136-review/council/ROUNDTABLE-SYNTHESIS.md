## 二、议题 1 终极定案：高保真 GitHub 组队模拟器与断面评测器架构（`teamgate-v2.mjs`）

综合 `R01 / R04 / R05 / R06 / R07` 的设计，新版模拟器评测器必须包含以下 5 层架构：

### 1. 引擎底座与在线钩子修正（100% 物理保真）
- 使用 `TGame`（继承 `src/sim/sim/game.js`，包含：① 组队模式配色 `cX.aKa` 抽 512 个随机数而非 3×AI；② 只有 `nTeams == 8` 时内置 AI 才入队，`nTeams < 8` 时内置 AI `team = 0` 人人可打；③ 每 32 拍刷新一次 `teamLand` 缓存供 80%/90% 猎杀提速使用；④ `boats.js::landAt` 单点航线落边界/水格时开出无接壤攻击线并在下一拍原数退回余额；⑤ 修复 `clone.js` 保持 `TGame.prototype`）。
- **强制开启在线环境标志**：设置 `g.online = true`，并注入完整的 `window` 钩子（`__tsbSquadSlot = slot`、`__quitPlayers`、`__hlLog`），使策略 100% 走线上真实代码分支。

### 2. 锁步时变指令通道层（Channel Emulator）
利用锁步等价定理（本地拍 $\tau$ 看到的状态即为服务器第 $\tau$ 拍状态），策略在服务器第 $\tau$ 拍被调用，发出的指令进入通道队列：
1. **单决策拍 1 令仲裁**：同一次 `act(g)` 内只受理第 1 条发出的指令（返回 `true`），同拍后续指令一律返回 `false` 丢弃。
2. **捐款静默拒单模拟**：`g.donate(pct, target, me)` 提交时，通道层始终向策略返回 `true`（模拟线上发包无同步回执）；到达结算拍时，若未通过引擎 `ao.ei` 配额校验或目标已非同队存活，静默丢弃且不扣费。
3. **五档到达延迟模型（Channel Profiles `C0 ~ C4`）**：
   - `C0`（理想零延迟对照）；
   - `C1`（正常线上通道：基础延迟 $d \in [10, 18]$ 拍，向上取整到 7 的倍数拍结算）；
   - `C2`（实录轨迹驱动：直接读取 `R01 channel_bursts.csv` / `R05 lag-staircase.json` 的真实逐号到达阶梯 $\text{Land}_i(\tau)$）；
   - `C3`（合成外生卡顿波：`t = 600 \sim 2400$ 期间各号按固定相位轮流静默 $15 \sim 35$ 个回合后一次放行）；
   - `C4`（发令自激耦合卡顿：静默间隔随编队最近 100 拍发令密度线性拉长）。
4. **连续 3 回合 9 条硬顶 + 同拍 LIFO 倒序结算**：
   - 每个服务器结算回合（`t % 7 === 0`），对每个席位收集到达拍 $\le t$ 的指令；
   - 可执行条数上限 $= \max(0, 9 - \text{前 2 个回合已执行条数})$；
   - 按发出顺序保留前 $K$ 条（并提供留最早/留最晚开关），超出的直接丢弃（不顺延）；
   - 同拍内按**后发先执行（LIFO 倒序）**逐条按当前余额实时计价结算！
5. **出生阶段送达模型（`S1`）**：支持模拟「首轮指派丢失 + 末拍同步多条 LIFO 倒序覆盖 + 0 条落地退回引擎默认随机格点」。

### 3. 三层评测模式与对手生态
1. **层 1：历史真局断面反事实重演（Counterfactual Checkpoint Benchmark — 主力检验）**
   - 从发现集真实录像的 4 类标准断面切入：`t = 0`（选点）、`t = 630`（抢内置 AI）、`t = 1500`（核心期开战）、`t = 3213 / 4284`（配额换档与解禁）。
   - **热身同步**：从 `t = 0` 空跑至断面拍以预热策略内部状态，在断面拍清空在途账本后正式接管我方席位。
   - **双臂配对（Control vs Treatment）**：同一断面、同一通道轨迹下，先跑当年旧策略（`Vb` 或 `c110`）作为对照臂（校验对照臂与历史轨迹吻合度），再跑新策略作为处理臂，只统计两臂成对差 $\Delta$。
   - **断面对手自适应反应补丁（`R` 档）**：其余玩家默认重放录像原指令（目标已死则改打最便宜相邻 AI/中立）；同时挂载反应触发器——若我方接壤号因新策略出兵导致密度跌破对手历史开火阈值、或我方先手进攻了存兵 $\ge 2$ 倍的强敌，对手按实测概率（46%）触发反击脉冲（`pct = 126`）。
2. **层 2：闭环多原型对抗竞技场（Full-Game Arena — 终局与抗压检验）**
   - 房间配置按实盘分布抽样（2 队 / 3~4 队 / 6+ 队，真人数 20 ~ 100，含同队野生路人 M1 与中途掉线空壳 M2）；
   - 敌方队伍配置 6 类实测原型对手（`O1` 攒兵猎手、`O2` 整仓喂大号战队、`O3` 固定档连压、`O4` 梭哈客、`O5` 跨海登陆猎手、`O6` 分阶段抱团）。

### 4. 五级门禁标准（G0 ~ G4）
- **G0（模拟器校准门禁）**：旧策略 `Vb` 在新模拟器中跑出的 6 项退化签名（同拍批占比、重复单占比、1530 拍相对领土、配额拒单率、目标已死改道率）必须落入实盘四分位区间。

- **G3（阶段产出与 P10 最坏分位）**：`t = 1500` 人均领土相对值提升 $\ge +20\%$，成对差 P10 最坏十分位不显著为负。
- **G4（配对整局胜率与编队自身份额）**：在 `C1`（正常通道）与 `C2/C3`（卡顿波通道）下，主队胜率与编队自身领土份额均显著优于 `Vb` 与 `Vc`。

## 三、议题 2 终极定案：超级版本（`v28-team-organism` + `spawn-coordinator-v28`）八大核心重构规格

综合 5 份 `COUNCIL-PROPOSAL.md` 的数学推导与边界护栏，超级版本由以下 8 个正交、可独立开关消融的模块组成：

### 模块 P1：全链路在途指令账本、防清仓连乘约束与单拍优先级仲裁（Channel Self-Defense）
- **解决病灶**：确认窗内重复下单（占出征兵 52%）、追帧 9 条同拍落地清仓（抽空 60%~99% 余额）、`expandNeutral` 1 格小单挤掉 `buyLand` 主力大单、`isNoFullSend` 7 拍窗口永久误锁。
- **数学与代码规格**：
  1. **本机在途账本 $F$**：拦截所有指令出口（`attack / donate / boatTo / retreat`），每拍最多只允许发出 **1 条**指令；发出的指令记入队列 $F = \{(t_{\text{issue}}, \text{kind}, \text{target}, \text{pct}, \phi, B_{\text{issue}})\}$。
  2. **事件驱动销账（不用固定拍数盲目过期）**：当观测到本号余额发生非利息扣减台阶、或 `g.attackTroopsOn(me, q)` 跳增、或 `g.boatCount[me]` 跳增时，匹配销掉 $F$ 中最早的对应在途单；若距上一条被确认落地的指令已超过正常窗口或通过 `performance.now()` / 余额台阶检测到客户端处于「追帧掉队状态（Stall Mode）」，则在收到新确认前**暂停发出第 2 条同目标指令**（掉队模式下严禁发捐款、发船和打健康真人，每回合最多发 1 条扩张令）。
  3. **连乘剩余余额预估 $\hat{B}$ 与防清仓硬约束**：
     $$\hat{B} = B \times \prod_{j \in F} \left(1 - \frac{\text{pct}_j + 1}{1024} - \phi_j\right)$$
     任何新指令加入后，必须满足连乘后余额不跌破当前安全底线：
     $$\hat{B} \times \left(1 - \frac{\text{pct}_{\text{new}} + 1}{1024} - \phi_{\text{new}}\right) \ge \text{keep}$$
     对目标 $q$ 的有效需求扣减在途量：$\text{need}_{\text{eff}}(q) = \max(0, \text{need}(q) - X_{\text{inflight}}(q))$。
  4. **单拍动作优先级仲裁**：在 `t >= P.dpEnd` 后，若当拍身边无主地很少（如 $\le 8$ 格）且 `buyLand` 存在划算目标（$c < \text{worth}$）或紧急反击需求，**先执行 `buyLand`，未发令时再执行 `expandNeutral`**，杜绝 1 格无主地挤掉主力进攻。
  5. **`isNoFullSend` 精确修复**：优先读引擎标志；若用余额差探测，仅在「账本 $F$ 中恰好只有 1 条指令刚落地确认且当拍无捐款收支」时检验，连续 $m \ge 3$ 次被截才置真，一旦出现足额落地立即复位为 `false`。
- **防坑护栏（`R01 / R04` 断面）**：
  - **护栏 1（紧急对冲反击豁免限速）**：当敌方真人压在本号身上的在途兵 `inHumanAtk` 正在增加且我方对冲槽不足时，允许按差额立即补发反击脉冲（保住 `A050 zexos1 4250` 拍 8 连发对掉 382 万来兵的正例）；
  - **护栏 2（显式首击斩杀额度）**：旧版靠重复单叠加才在 `t=1500` 一击打死弱敌（`A023 / A031 / A050 / A003`）；上了在途账本不重复发单后，若目标 $q$ 是可一击打穿的弱敌（`1.25 * need <= B - dpKeep` 且无第三方大号夹击），允许单笔直接按完整 `1.25 * need` 发出（将旧版 3 条连发的兵合并为 1 条足额指令，既打死目标又省下 2 次 1.17% 手续费！）。

### 模块 P2：选点协调器重构——Voronoi 面积最大化、定稿冻结与单步单令送达（Spawn v28）
- **解决病灶**：扇形阵把 `0.95 * rCell` 当间距导致 Voronoi 天然份额仅 `0.55~0.61`、空盘 `t=-42` 盲目锁死内陆角、末拍因 `rCell` 变化翻转朝向 125°、首轮指派丢失（675/686）、同拍多令 LIFO 倒序盖回旧点造成 20 局同像素叠点。
- **数学与代码规格**：
  1. **房间精准隔离（防平行房间串台）**：`matchKey` 结合房间已落点真人名字指纹，且只为当前房间实际在场的我方席位排阵（解决 `A043 / A017 / A094 / A075` 串台与空槽）。
  2. **按 Voronoi 天然地盘最大化选址 + 逐点敌距硬约束**：
     - 废除 `0.95 * rCell`（封顶 68px）的过度紧缩扇形，将队友目标间距拉宽至公平间距量级（$1.45 \sim 1.85 \times r_{\text{Cell}}$，动态适配连通陆地面积），内圈无前线号最多保留 **0~1 个**，其余全员分布在外弧拥有独立 AI 扩张扇面；
     - 候选方案评分直接计算**「我方 $K$ 个点在当前盘面上的 Voronoi 陆地总格数 + 周边可通行陆地净空」**，并对**每一个落点**施加与已落点敌方真人的硬性最小安全距离约束（解决 `A005 talon5 / A034 ryan_m / A095` 贴敌落子）。
  3. **两阶段定稿与末拍冻结（Freeze Window）**：
     - 废除 `t = -42` 空盘锁角；在选点前中期跟随敌方落子更新，但在距离开局最后 `8` 步进入**定稿冻结期**：除非某号当前落点被后落子的敌人贴脸入侵（$< d_{\text{danger}}$），否则严禁重排全队坐标或交换队友点位！
  4. **客户端闭环确认重发 + 每步限 1 令（破除首令丢失与 LIFO 倒序覆盖）**：
     - 客户端对照自身在引擎中的真实出生框中心 `(g.x0+g.x1)/2, (g.y0+g.y1)/2` 与目标点 `(tx, ty)`：只要真实位置尚未落到目标点附近（或 `curX < 0` 未落子），每隔固定步数（如 3 步）持续重发当前目标点（解决 `A070 / A026 / A003` 首令丢失后 0 条落地被随机乱扔）；
     - 同一选点步内每个号绝不发送第 2 条不同坐标的选点指令，彻底根除同步 LIFO 倒序旧点盖新点！
  5. **统一战队标签（针对 `c110` 拆队病灶）**：组队模式下全员携带统一战队标签确保引擎 `dP.ee` 将全队分入同一队伍，同时策略内 `isOurSquadBot` 优先按同队（`g.teams[p] === g.teams[me]`）与当局面名册识别，彻底消除跨队互锁、撞名野人（`Prussia / Zoro / 777`）与给掉线空壳捐款。

### 模块 P3：`t < 1500` 与 `t >= 1500` 抢内置 AI / 吃空壳底线解耦（AI & Carcass Floor Unblocking）
- **解决病灶**：`threatOf -> safeFinite` 把同队队友、掉线空壳当成威胁（锁死 37%~54% 决策拍），且为 0 兵 AI 留出几十万兵底线；`t >= 1500` 因 `dpKeep` 按最强真人邻居一刀切导致吃不动身边 0 兵 AI 与掉线空壳；`c110` 因 `minCmd`（4.7% 余额）跳过所有残余 AI。
- **数学与代码规格**：
  1. **`threatOf(g, p)` 过滤队友与空壳**：计算 AI 邻居 $q$ 的其他邻居最小余额时，**跳过同队队友（`this.isTeammate(g, o)`）、同编队号以及已掉线空壳（`g.state[o] === 2`）**。
  2. **`safeFinite` 按 AI 自身威胁封顶**：为 AI 邻居 $q$ 预留的防偷袭底线，绝不超过该 AI 自身打得出的兵力上限：
     $$\text{safeFinite}(q) = \min\left(\text{minEnemyNeighbor}(q) - \text{outAtk}(me, q),\; \theta_{\text{AI}} \cdot B_q + 2 \cdot \text{border}(me, q)\right)$$
     当 AI 余额 $B_q \approx 0$ 时，不再因为它背后站着一个大号就锁死我方吃 0 兵 AI 的手！
  3. **吃 0 兵残部 / 掉线空壳 / 残余 AI 的 `dpKeep` 局部解耦与 `minCmd` 修正**：

- **防坑护栏**：保留对活跃健康真人邻居的 `dpKeep` 防守底线，吃 AI/空壳的单笔支出严格受 `0.15 * B` 与防清仓不等式约束，确保 `t=1500` 开战时不因过度花兵而裸奔。
