# 探针随 Cursor 环境自动部署（install / start）

目的：让每台跑 agent 的 Cursor 云机器在**开机时自动**带上桥运行时（`dais_runtime.pyz` +
`~/.cursor/hooks.json` + 心跳守护），不再靠 agent 自己在提示词里执行安装命令，从而把它对
模型「藏起来」——提示词不提、机器上不留明文配置、命令里不带地址。

## 两种装法

### A. 平台装（推荐）：在 Cursor 环境配置里写 install + start

在你跑这些聊天的 Cursor 环境里加（Cursor 后台 → 环境设置，或仓库根 `.cursor/environment.json`）：

```json
{
  "install": "mkdir -p ~/.cursor && curl -fsSL \"${DAIS_SRC:-http://127.0.0.1:8787/trace/dais_runtime.pyz}\" -o ~/.cursor/dais_runtime.pyz && chmod +x ~/.cursor/dais_runtime.pyz",
  "start": "python3 ~/.cursor/dais_runtime.pyz install >/dev/null 2>&1 || true"
}
```

- **install**：做环境镜像时跑一次，把运行时包下进镜像。**只有这一处会出现服务器地址**；
  强烈建议把真实地址放进 Cursor secret（变量名如 `DAIS_SRC`）注入，别写死进仓库（上面的
  `127.0.0.1` 只是占位默认）。
- **start**：每台机器每次开机跑一次。`install` 子命令会写好 `hooks.json`、起心跳守护；
  地址已经**内嵌进 pyz**，所以这条命令本身不带任何地址。
- 装好后，agent 的提示词、长等待命令里就都不用再提探针/安装了。

限制（来自 Cursor 环境机制，需配合桥端兜底）：

1. `start` 不会被等待：开机到它跑完之间有几秒空档；失败也不报错，只写日志。
   → 桥端保留「agent 已在线、但该机器没有探针心跳」就报警的兜底。
2. 和 agent 同一个系统账号，能防漏装 / 误伤，**防不了故意删**（这条已确认无所谓）。
3. 只对新开的机器生效；镜像里的 `~/.cursor` 开机后会不会被 Cursor 重置尚未完全验证，
   所以用 `start` 每次开机重写一遍兜底。

### B. 一条自装命令（过渡 / 应急）

不改环境配置时，可在任意机器手动跑一次（地址已内嵌，无需带地址参数）：

```bash
[ -s ~/.cursor/dais_runtime.pyz ] || (mkdir -p ~/.cursor && curl -fsSL "$DAIS_SRC/trace/dais_runtime.pyz" -o ~/.cursor/dais_runtime.pyz && chmod +x ~/.cursor/dais_runtime.pyz)
python3 ~/.cursor/dais_runtime.pyz install
```

## 配合的代码改动（本分支已做）

- 服务器地址以 XOR+base64 混淆编译进 `dais_runtime.pyz`；安装时机器上**不再落**明文
  `agent_trace_config.json`（并自动清掉历史明文配置）。
- 长等待命令不再携带明文地址（`wait` 子命令自己读内嵌默认）。

## 待定（等你拍板平台装 A 并上线后再做）

- 把 join / duty 提示词里「首次启动先在终端运行一次运行时初始化：curl … install」那几行删掉，
  以及长等待命令里残留的 `curl … /wait` 兜底分支去掉——届时提示词 / 命令里**彻底**不出现探针与地址。
- 这一步要等平台装生效后做，否则没有平台装的机器会漏装探针、丢追踪与防断连。
