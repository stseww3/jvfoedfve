# sky/tones 明暗检查脚本

## 目标
方案第 11 节 A2 行的验收“天空最暗，墙是中间调，窗和灯最亮；没有死黑”，和评分标准的“明暗和光色”一项，做成能对任何一张图跑的检查，给评审、交叉看和每批看板回看用。

## 约束
- 输入一张图（真机图或离线图），输出：去色图；按灰度分成暗、中、亮三级的色块图和各自占比；死黑（灰度低于 0.03）的面积；亮区（灰度高于 0.6）的面积和它的重心；暖色、冷色各占多少。
- 一张图几秒钟，只用 numpy 和 Pillow，可以在云端机器上对回传的图跑。
- 不做判定，只出数和图；线由评分标准定（亮区不超过三分之一，没有成片死黑）。

## 交付物
- `build/scenes/obs/sky/_tones.py`（名字带下划线，不被自动发现），命令行：`_tones.py <图> [--out <文件夹>]`，一次可以给多张。
- 不需要测试场景；用 `sky/look` 光线板的图当样例，结果图附在【交付】里。

## 验收
- 对光线板的三张图（A、B、C）跑出来的三级占比和 `sky-notes.md` 第 7 节的阶梯对得上。
- 评审用它看过一张图，说够用。

**用法**（云端，在 `build/` 里；只读图、不出图、不碰场景。不带 `--out` 一张图两秒上下；带 `--out` 要画对照图，合用机忙的时候一张要一分钟（cr2 量的，#57797），成批的投到节点上）：

```
nice /agent/realms-study/.venv/bin/python scenes/obs/sky/_tones.py <图> [<图> ...] [--out <文件夹>]
    [--probe 名字=x0,y0,x1,y1 ...] [--probes <表.json>] [--diff <另一张图>] [--diff-over 数]
    [--mask 名字=<黑白图> ...] [--mask-out <黑白图>] [--order median|mean] [--luma 601|709]
    [--look A|B|C] [--shots <场景的 shots.json>]
    [--ladder] [--crop x0 y0 x1 y1] [--split 数] [--parts] [--json <文件>]
```

- 不带 `--out` 只打数；带了每张图另出一张对照图 `<图名>-tones.jpg`：原图、去色图、三级色块图、冷暖图，下面是数、直方图，和 96 像素宽的原图、去色图、色块图（邮票大小读不读得出三级就看这三张小的）。`--parts` 另存去色、色块、冷暖三张原大的图。
- `--probe` 量一个框：像素数、平均、中位、最亮的 1%、最暗的 1%、平均色、冷暖占比；给几个框就从暗到亮排一行（原来按平均，11-16 跟进起按中位，见下），“天 < 墙 < 窗”直接读。四个数是矩形 `x0,y0,x1,y1`；六个数以上是多边形的顶点，一对一对 `x,y` 地写（斜的边石线、梯形的台阶带用它）。坐标是像素，所有数都不超过 1 就当成占画面的比例；对照图左上那张原图的边上每十分之一有一道刻度，照着读，框也画在这张图上，放歪了看得出来。像素数少的框，“最亮的 1%”只是一两个像素的值（不足 100 个像素时就是最亮的那一个），看像素数判断这个数靠不靠得住。`--probes` 是按图名写好的框表（`"*"` 对所有图），样例见 `plan/parts/figs/tones/probes.json`。
- `--diff <另一张图>` 是同一个机位的另一张图（开关开和关、甲版和乙版），大小要一样。两张图亮度差超过 0.02（`--diff-over` 改）的像素就是“变了的那一块”的脚印：报它占画面多少、比另一张亮的和暗的各占多少、成不成片，再报这些像素在这张图里（here）和在另一张图里（there）各自的像素数、平均、中位、最亮 1%、最暗 1%。同时给了框的话，每个框另报“框里变了的像素”的同一组数。对照图多一排：另一张图，和脚印图（比另一张亮的标橙，暗的标蓝）。雪、台阶浅带、灯链这类“开和关各一张”的验收用它：山坡上不规则的雪矩形框不住，相减得到的正好是雪的脚印。脚印只比亮度，不比色相。另有一行 `pixel for pixel` 不看阈值：红、绿、蓝三个通道逐个比，报有多少个像素的值不一样、最多差 255 里的多少；要证明“开关开和关，外立面一个像素不变”（总监 #32701 第 4 条给 `windows.LINING` 的硬条件），看这一行是不是“not one value differs”。
- 11-16 跟进加的几样（**还没跑过**，见最后一条记录）：
  - 框的那一行按**中位**从暗到亮排（评审报的都是中位；带窗棂的窗、带灯球的框，平均和中位差很多），行尾写着 `(medians)`；`--order mean` 回到按平均排。`probe` 行和 `differs within` 下面的 here / there 两行写三位小数（壁柱和墙只差 0.02，两位分不出）；`order` 行和整张图的数还是两位。

**量法**：
- 亮度是图上像素值的 Rec.601 灰度（0.299 R + 0.587 G + 0.114 B，0 到 1），就是 PIL 的 `L`，跟 c205 量亮窗用的一样。
- 死黑：低于 0.03。亮区：高于 0.6。死白：高于 0.97。这三条线不随光线版本变。
- 暗和中的分界随光线版本：A 0.18，B 0.12，C 0.25，取在“屋面以上的天”和“只有天光的墙”中间（`sky/look` 量的：A 0.13 和 0.24，B 0.05 和 0.17，C 0.20 和 0.29）。版本从图旁边的 `shots.txt` 里那张图的时刻认（12300 到 13400 是 C，15500 到 21500 是 B，其余是 A）；收图夹里的图没有 `shots.txt`，给 `--shots` 或 `--look`；都没有按 A。
- 暖：红比蓝高 0.03 以上；冷：蓝比红高 0.03 以上；其余算中性。除了总占比，还分开报暖色、冷色各落在暗、中、亮哪一级（“冷暖对比落在灰白石上”看中间那一行）。
- 成片：把图分成约 320 格宽的粗格，一格里过半才算，上下左右相连的算一片；报片数和最大一片有多大（占画面多少、折成正方形边长几个像素）。零星的噪点不算成片。
- 亮区的重心是亮像素的平均位置（左上是 0 0），另报九成亮像素落在哪个框里，色块图上画了十字和框。
- 只出数和图。亮区不超过三分之一、没有成片死黑这些线是评分标准的，过不过由评审说。
