# 成品地图导出（export）— 工作包卡片

类别：common。包名：`export`。优先级 P1：现在做空跑，评审都过了以后做正式的一次。总监 11-16 立（第二批）。

## 目标
把总装变成一个能直接上传的成品存档：一条命令导出；导出的包在干净的 26.3 服务器和客户端上打开，12 张看板图和总装的看板对得上。现在就空跑，把只有导出才会露出来的毛病早点找出来。

## 约束
- 设置照 `plan/STATUS.md`「成品地图交付清单」逐条做，不自己加减。清单里写着“等总监”“没有人定”的（游戏模式、其余游戏规则、出生时面朝哪里），列成一张表问总监；没回话以前照测试服 `build/place.py` 的 `RULES` 做，并在报告里标明哪几条是暂定。
- 成品世界里只有整场 `obs`。各包的测试场景、光线板、试验时刻、箭头测试卡、`ph_` 占位贴图都不进（清单里 sky 的收尾、占位贴图两条）。
- 资源包跟着存档走，数据包在世界的 `datapacks/` 里。Realms 上传对大小、资源包、数据包、视距的规定以官方文档为准：查到的写进报告并给出处，查不到的写「没查到」，不猜。
- 游戏文件只从官方地址取；不用管理员的电脑；真机在 s1（c319）的节点上，用之前和他约。
- 成品包是大文件：不进总装，推到单独的分支 `cursor/c164-dist-<后缀>`，一次导出一个提交；不走桥。

## 件清单
1. `tools/export.sh`（或 `.py`）：从一个总装提交出发，建世界、摆整场、跑清单里的命令、打资源包和数据包、清掉玩家数据和测试用的记分板、压成 zip。同一个提交导两次，除了时间戳，世界文件一样。
2. 进服那一下的设置（方块交互距离设成 0 等）写成数据包里的函数：对每个新进来的人生效，重进也生效。
3. 空跑报告 `plan/reviews/export/<总装头 7 位>.md`：包的大小、区块数、实体数（展示实体和别的分开）、循环开着时服务器每刻用时（空场、1 个玩家）、头一次进服到能动要多久、清单逐条核对的结果、导出的世界里拍的 12 张和总装看板的对比（请 s1 拍）。
4. 上传说明一页：管理员拿到 zip 以后怎么传到 Realms，传完看哪几样。

## 验收
干净环境里从 zip 起服：进服就在 V1 的站位，朝向对；时间和天气不动；点不动方块；循环自己起来；12 张图和看板对得上，差别逐条说明。报告里每一条写明验过还是没验。

总装、`build/place.py`、`tools/realshots.py`、s1 的真机、a2（motion 循环怎么起）、s2（交付清单）。
