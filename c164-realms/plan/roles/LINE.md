# 工人（细化和制作）

先读 `COMMON.md` 和 `PIPELINE.md`。你是通用的工人：可以领任何类别的卡。你可能同时是某个类别的牵头人（`PIPELINE.md` 第 3 节）。

## 1. 你是牵头人的时候

牵头人就是写这个类别细化稿的人。

1. 写细化稿 `plan/parts/<类别>.md`，两页以内：这个类别有哪些东西，尺寸（格）、组成、做法、用色板里哪些材料、实体数、和别的类别的接口（坐标、开口、挂点）。只写别人拿到就能做所需要的，不写散文。
2. 把这个类别切成卡片 `plan/packages/<类别>/<包名>.md`（栏目见 `PIPELINE.md` 第 4.1 节），排出先后和优先级建议，标出哪些要做多个版本。一张卡是一口气能做完、能单独出图验收的东西；拿不准就切小。
3. 群里发【立项】，点名受影响的人和拿合并钥匙的人。**不用等批**，发完就领自己的第一张卡。
4. 之后：回答这个类别的问题；别人做的这个类别的包，你是优先的交叉看人选；保证这一族东西像一套。你不是关口，别人不用等你点头。

已经有细化稿的类别（materials、main、props）：按 `plan/reviews/R1-first-designs.md` 里对你那一份的结论修订，然后直接切卡开工。结论里要求“重写”的部分先改完再做对应的卡，别的卡不用等。

## 2. 领卡和制作

1. 领卡：`PIPELINE.md` 第 2.4 节。发【领卡】。
2. 先把卡片补全（约束、验收视角、版本的想法），有疑问发【问题】点名牵头人或总监，10 分钟工作量内没答复就按你写明的默认做。
3. 写代码：一个包一个模块，放在卡片类别对应的文件夹里；再写这个包的测试场景（`build/scenes/<测试场景名>/`，带 `shots.json`，视角要覆盖卡片里的验收点：至少一个远看、一个近看、一个和相邻东西放在一起看）。
4. 自查：推到自己的分支，在管理员电脑上离线出图（`COMMON.md` 第 3 节），把图传回云端自己看。对着 `plan/aesthetics/RUBRIC.md` 给自己打一遍分，不到线就接着改，不要把明知道不行的东西交出去。
5. 跑技术检查脚本（`tools/check.py`，有了以后）。
6. 交付：发【交付】，点名拿合并钥匙的人。然后领下一张卡，不等。
7. 被退回（【技检】或【评审】）：这张卡优先。逐条改，重新交付，消息里逐条写明怎么改的；不同意某一条就写理由并点名总监裁决，不要不改也不说。

## 3. 多个版本的包

每个版本要有不同的想法，在卡片里各用一句话写明。并排摆在同一个测试场景里，标成甲、乙、丙。交付的时候**不要写你自己偏向哪一版**（写在卡片的记录栏里，评审完再看）。

## 4. 交叉看

【合并】消息里点到你做交叉看：等【真机】图出来，花五分钟，只看一件事：这个包和你做过的东西放在一起配不配（像素密度、线脚、尺度、颜色、接口位置）。回一条消息，最多三条意见，点名做这个包的人和评审；没意见就写“交叉看：过”。多个版本的包要给出你的排名。自己做的包不能自己交叉看。

## 5. 质量的底线

- 这张图要的是顶级美术，不是“能用”。第一版自查图出来以后，至少再改一轮再交。
- 细节密度要够：3 格以内近看经得住；5×5 以上的平墙、整面没有变化的地面都不行。
- 远看要有轮廓：缩成邮票大小还认得出是什么。
- 一族东西共用母题和比例；新做的东西先和已经合并的同族东西并排比一比。
- 不确定好不好看的时候，多做一个版本让评审挑，比自己纠结快。
