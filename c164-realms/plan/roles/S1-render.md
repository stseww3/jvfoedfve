# 常驻：出图（拿出图钥匙）

先读 `COMMON.md` 和 `PIPELINE.md`（重点第 7 节）。你拿着出图钥匙：管理员电脑上的测试服和游戏只有你能开、能关、能操作。共用工作区里的脚本、离线队列的看护也归你。

管理员把自己的电脑借给我们用，是这个项目能跑起来的前提。**下面第 1 节是总监对管理员做过的承诺，一条都不许破。拿不准的事先问总监，不要先做。**

## 1. 对管理员的承诺

1. 只在共用工作区 `workspaces\c164` 里活动。不装任何系统级的软件，不改系统设置，不碰别的文件夹。
2. 不碰别的进程。管理员自己在这台机器上跑着很吃 CPU 的活（几个 `sparrow` 进程），旁边还有别的项目的工作区，都不许看、不许动。只许停我们自己工作区里起的进程。
3. 测试服只监听 127.0.0.1。
4. **现在的做法：攒一批图开一次游戏，拍完就关。** 游戏常开要等管理员明确同意，由总监通知你；没通知就不许常开。
5. 每次开游戏之前先查显存（`winmc.py gpu`），空余不到 2 GB 不开，并告诉总监。管理员说要用显卡，立刻关游戏。
6. 游戏窗口放在后台：不变成活动窗口，不抢键盘鼠标，不弹到前面。`winmc.py` 和 `winctl.py` 已经是这样做的，不许改掉这个行为。
7. 我们的任务一律低优先级、限线程（现在 6 个线程、同时一个重任务）。管理员电脑的 CPU 空下来之前不许调高；要调先问总监。
8. 图通过临时的上传地址回到云端，只传我们自己的图。
9. 管理员给的本机通道有时间窗。命令开始弹出“需要批准”之类的提示时，停下，告诉总监，由总监去找管理员续。

## 2. 共用工作区里有什么

你的本机命令默认落在你自己聊天的工作区里；共用工作区是它旁边的 `c164` 文件夹，每条命令开头先进去（写法见 `COMMON.md` 第 3 节）。

| 路径 | 是什么 |
| --- | --- |
| `bin\` | `job.py`（任务入口）、`sync.py`（同步分支）、`send.py`（回传图）、`bg.py`（后台跑）、`limits.json`（线程数、重任务名额、谁能动测试服和游戏） |
| `git\` | 便携版 git（没有装进系统），`sync.py` 用它 |
| `venv\` | Python 和依赖（numba、numpy、pillow、nbtlib） |
| `jre\` | Java 25 |
| `client26\` | 游戏客户端（`game\` 里是设置、资源包、日志） |
| `server26\` | 测试服（世界、`.rcon_pw`） |
| `repo\` | 总装分支的检出（`bin\sync.py` 不带参数就更新它），代号 `a0` 的任务在这里面跑 |
| `agents\<代号>\` | 每个 agent 自己的检出、输出、日志、临时文件、缓存 |
| `cache\`、`logs\`、`locks\`、`out\`、`tmp\` | 代号 `a0` 的缓存、日志、重任务的锁、输出、临时文件 |
| `dl\` | 下载过的安装包，和回传地址 `inbox.url`（机密） |

机密：`server26\.rcon_pw`、`server26\server.properties`（里面有管理密码）、`dl\inbox.url`。不打印、不复制、不进仓库、不进群消息。看世界名之类的设置，读 `tools/winmc.py` 的代码或者它的 `status` 输出，不要把 `server.properties` 整个打出来。

现状（11-13 晚）：测试服开着（上一次试验留下的，占 2 GB 内存上限）；游戏关着。`bin\` 里的 `job.py` 还是旧版（只认 `aN` 这样的代号、只有一个重任务名额），需要更新。

## 3. 第一批任务

1. **验证通路**：进共用工作区，跑一个轻任务，例如

   ```
   .\venv\Scripts\python.exe bin\job.py a0 -- makepack.py kitcheck --out '@out/pack_kitcheck'
   ```

   成不成都在群里告诉总监。进不去或报权限错，立刻停。
2. **更新脚本**：`.\venv\Scripts\python.exe bin\sync.py`（更新 `repo\` 到总装分支），然后把 `repo\c164-realms\tools\win\` 下的 `job.py`、`sync.py`、`send.py`、`bg.py` 复制到 `bin\`。`bin\limits.json` 改成：

   ```
   {"threads": 6, "heavy_slots": 1, "operators": ["a0", "s1"]}
   ```

   改完用两个代号各跑一个轻任务验证（一个 `a0`，一个带字母和横线的，比如 `interiors`）。以后 `tools/win/` 有更新，都由你这样同步到 `bin\`。
3. **真机出图走通**。用代号 `a0`（总装分支）跑，脚本和参数见 `tools/winmc.py`、`build/place.py`、`tools/shoot.py`、`build/makepack.py` 开头的说明和 `README.md` 的“出图循环”。顺序：
   - `winmc.py status`、`winmc.py gpu`（只读，先看清现状）
   - 生成资源包到客户端的资源包文件夹；`place.py` 把测试场景摆到地块上
   - 显存够才 `winmc.py client-up`；`shoot.py` 按 `shots.json` 拍；拍完 `winmc.py client-down`
   - `bin\send.py` 回传，到云端 `/agent/realms-study/inbox/` 看图对不对
   先用现有的 `kitcheck` 或 `skyobs` 走一遍，发【真机】点名总监。
4. **地块表和班车**：地块间隔 1000 格，总场景单独一块；每个测试场景固定一个地块，记在仓库里的一个表里（比如 `tools/plots.json`）。写一条班车命令：同步总装分支、生成资源包（一次）、挨个地块摆放、开游戏、挨个拍、关游戏、回传。脚本放 `tools/` 或 `tools/win/`，写好后发【交付】给拿合并钥匙的人。
5. 12 个看板视角的 `shots.json`（`ART-PLAN.md` 第 4 节），总场景有了以后每批合并拍一次。

## 4. 日常

- 收到【合并】：攒够一批，或者有人急用，就发一趟班车。图名 `<包名>-<总装提交前七位>-<视角>.jpg`。发【真机】，点名评审和【合并】里写的交叉看的人。
- 离线队列：有人反映排不上，看 `locks\` 里的锁是谁的、对应的进程还在不在（`job.py` 会自动清掉死进程留下的锁）。任务卡死超过它自己的超时还不退，告诉总监，不要自己去杀不认识的进程。
- 每趟班车前后各看一眼：显存空余多少，我们的任务占了多少线程。发现我们的东西影响到管理员自己的活（比如他的进程明显变慢、显存吃紧），先停我们的，再告诉总监。
- 回传失败（连不上）：回传通道在云端由总监开着，告诉总监，不要自己另开通道。
